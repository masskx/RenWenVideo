# 风格指南（style-guide）

> 这份文件收的是**从外部仓库学来、已经改写成本项目做法**的风格知识，每学一个仓库加一节，注明来源。
> 规则的先后不变：根目录 `CLAUDE.md` 和 [video-craft/quick-reference.md](video-craft/quick-reference.md) 优先（钩子 → 留人 → 手机看得清 → 忠于素材 → 打磨）。这里的内容都属于第 5 条“打磨”，以及帮第 1、2 条的手段；和速查页冲突时以速查页为准。
> 2026-10-22 起，本项目自己的画面口味以速查页 §六“高级感”为准（cinema 主题：一个主角、一个金色强调色、不加装饰）。下面学来的手法都要在这个口味里用：组件配色用金色 / 红色，花字、爆炸框这类“响”的东西少用。
> 本项目的片子：9:16 竖屏（1080×1920，30 fps），一般 30–40 秒，AI 工具 / AI 新闻的知识类内容，节奏快，用本人复刻音色口播，语速约 1.2–1.25 倍（约 5–6 字/秒）。

### 一、这个仓库是什么，和我们差在哪

15 种动态设计（MG）风格，每种一支 **10 秒**成片，全部由 Claude Opus 5.5 写代码完成，不用图像或视频生成。画面是网页（SVG / Canvas / WebGL / Three.js，3D 那支用 Blender），每支片子提供 `window.renderAt(t)`，由无头 Chrome 逐帧截图，再用 ffmpeg 合成；音乐和音效也是代码合成的（`audio.py` + 自带的采样库）。每种风格公开：成片、风格说明、完整提示词、全部源码。每支片子都经过“AI 评委打分 → 按意见改”两轮，终评 7.57–8.21 / 10。

| | mg-styles-15 | 本项目 |
| --- | --- | --- |
| 长度 | 10 秒，一个镜头讲一个风格 | 30–40 秒，6–9 个场景讲一件事 |
| 声音 | 只有音乐和音效，没有口播 | 口播为主（字幕逐字对齐），底乐压低、音效点到接触帧 |
| 评判标准 | 风格还原度、惊艳度、动效手艺（评委打分） | 钩子、留人、手机上看得清、忠于素材，最后才是打磨 |
| 画幅 | 大多 16:9；花字那支 9:16 | 全部 9:16，要避开平台界面 |
| 技术 | 手写网页 + 自己的渲染器 | Remotion（同样是“每一帧只取决于时间”） |

所以我们**拿的是手法，不是整套风格**：一个 10 秒的风格展示片追求“一眼认出风格 + 一个高光”，而我们的片子要让信息一条接一条地进到观众脑子里。

### 二、拆解：动画节奏

**通用骨架（所有提示词共有）**：0.5 秒内必须有钩子（开头空镜或黑场不超过 0.3 秒），然后升级，在片长 60–75 % 处放一个“高光时刻”，最后一个构图完整的结束画面停 0.8–1.2 秒，并且留一点微动。画面和声音读同一张节拍表（`cues.json`）。

**两支和我们最接近的片子，节拍实测**（从它们的 `cues.json` 读出）：

| 片子 | 镜头 / 停点 | 事件密度 |
| --- | --- | --- |
| 综艺花字（18-hanazi，9:16） | 4 个镜头：2.5 / 1.5 / 3.5 / 2.5 秒 | 每 0.07–0.6 秒一个事件：标题逐字 2 帧错开，问号 2 帧错开，音效卡在画面事件上 |
| 回形针式科普（19-paperclip） | 镜头停点 0 / 2.7 / 4.35 / 5.62 / 7.0 秒（每个信息点 1.3–2.7 秒） | 飞行 0.65–0.9 秒，停下后继续轻微漂移；每到一个点必有一个新元素：贴纸落下、引线、表格亮起、柱子生长、数字滚动 |

**换算到我们的片子**（1.2–1.25 倍语速，约 5–6 字/秒）：

| 时段 | 节奏 |
| --- | --- |
| 0–3 秒（钩子） | 每 0.5–1 秒一个变化。第 0 帧就有落定的标题（`KineticTitle` 的 `at` 设成负数），第一句口播 0.5 秒内开始 |
| 正文每句（≤ 16 字 ≈ 2.5–3 秒） | 每句至少一个新视觉元素（回形针“解说词逐句驱动画面”）；一句里有数字就让数字成为那一下 |
| 每个场景（4–8 秒） | 1 个主动作 + 1 个高光；高光放在场景后半（约 60–75 % 处），和片子级的高光一个道理 |
| 场景之间 | 能在同一张画布上连起来的，用相机飞过去（`CameraRig`），不能的才切（`CutStage`） |
| 结尾 | 结束画面停 0.8–1.2 秒，带呼吸或漂移，不要死帧 |

**出现时机**，补充本项目原有规则（`enter` 比关键词早 0.06 秒）：

- **信息**（被念到的名词、数字、标签）卡在词上，甚至早 1–2 帧，眼睛和耳朵同时到。
- **反应**（爆炸框、印章、问号、震屏）比它回应的那个字晚 **2–3 帧**，像观众自己的反应，更自然（花字片的规则）。`BurstCallout` 默认 `lag = 3`。

### 三、拆解：动效参数

提示词里的“签名特征”都写成可检验的数字。这里把可以直接用的数字收在一起，对应的组件在 `src/components/`：

| 动作 | 参数 | 组件 / 函数 |
| --- | --- | --- |
| 弹出 | 缩放 0 → 1.15 → 1，约 8 帧（阻尼弹簧，第 5 帧到峰值） | `popScale`、`KineticTitle` |
| 逐字 / 逐个错开 | 2 帧（字），2–4 帧（元素）；同一时刻只让一个主体动 | `KineticTitle` 的 `stagger` |
| 弹性缓动 | `cubic-bezier(0.34, 1.56, 0.64, 1)`；“预备 → 冲出 → 回弹”三段 | `curve.overshoot` |
| 被甩出的东西 | `cubic-bezier(0.22, 1, 0.36, 1)`，绝不匀速 | `curve.flung` |
| 变形 / 相机飞行 | `cubic-bezier(0.7, 0, 0.3, 1)`，两头各留约 3 帧缓冲 | `curve.morph`、`CameraRig` |
| 线条描出 | `cubic-bezier(0.65, 0, 0.35, 1)`，全片线宽不变 | `curve.draw`、`DrawPath` |
| 锁定框 | 四角从 1.4 倍收到 1.0，快出缓入 | `LockOn` |
| 数字跳变 | 随机跳 3–5 帧后落到真实值 | `ScrambleText` |
| 数字滚动 / 柱子生长 | 缓出、**不过冲**（本项目补充：数据不能显示一个它没有的值） | `CountUp`、`GrowBars`、`curve.data` |
| 贴纸 | 8–12 px 统一白描边；从 1.35 倍带 6° 倾斜和抬高的投影落下，接触后衰减晃动 | `StickerSlap` |
| 挤压拉伸 | 位移时约 10 %（已有 `src/fx` 的 `squash` / `impulse`） | — |
| 驻留时保持活性 | 轻微摆动（≈ 1–1.5°）、上下 3 px、呼吸 1 %；知识类默认不摆 | `holdWiggle` |
| 线条“呼吸”（line boil） | 每 2–4 帧重画一次轮廓；**只用在装饰上**，默认关 | `BurstCallout` 的 `boil` |

### 四、拆解：转场

对方的规矩是“转场由元素带动，不用叠化”：色块擦除、某个元素飞出去顺带把整场换掉、一个形状长大盖满全屏、在大画布上一镜到底。

- 我们已有的 `CutStage`（横扫、圆形遮罩、推移、故障、翻页）符合“元素带动”，继续用；**不用叠化**。
- 新增的做法是**一镜到底**：同一个话题里的几个信息点（流程的几步、前后对比、逐条增长的清单）铺在一张画布上，用 `CameraRig` 飞过去。飞行 0.6–0.9 秒，途中先稍微拉远，让观众看到要去哪里。
- 竖屏上相机尽量**上下**飞：左右飞会把内容推到右侧按钮列下面。

### 五、拆解：字幕和版式

**花字的三层结构**：填充色 + 粗白描边 + 彩色外描边 / 硬投影；多层描边圆体字，高饱和撞色。在网页上就是同一个字叠三层，`paint-order: stroke fill` 让描边只露出外半圈（`KineticTitle look="hanazi"`）。

我们的用法：

| 文字 | 做法 |
| --- | --- |
| 跑动字幕（逐句口播） | 维持现状：60 px、单层深色描边、**静止**（只有 0.94 → 1 的轻微弹入）。不逐字弹、不摆动，字幕是用来读的 |
| 钩子标题、章节标题 | `KineticTitle`（clean）：逐字弹出，≥ 80 px，可以轻微摆动 |
| 情绪关键词（“被偷了”“免费”“翻倍”） | `KineticTitle look="hanazi"` 或 `BurstCallout`，**每个场景最多一个** |
| 数字 | 等宽数字（tabular-nums），滚动不左右抖；大数字 + 小说明（回形针结尾卡：粗黑体、超大数字、一行小字） |

**版式**（对方的评审清单里反复出现）：四周约 5 % 安全边距、严格对齐网格、一屏一个主角、粗细对比明显的字重层级、留白；中文标点正确，不能出现缺字方框或回退字体。本项目的安全区（[讲解动画规则.md](video-craft/讲解动画规则.md) §三）比 5 % 更严，以它为准。

### 七、拆解：组件结构（对方的代码怎么组织）

- **每一帧是时间的纯函数**：带种子的随机数、闭式的物理和粒子，不读真实时钟，不用状态触发的 CSS 过渡。这和 Remotion 的要求完全一样，本项目的 `src/fx` 也是这么写的。
- **一张节拍表**：`cues.json` 记录所有命中时刻，画面代码和 `audio.py` 都读它。我们的对应物是口播逐字时间戳生成的 `{a}` `{b}` 卡点：画面用 `cue('a')`，音效用 `Scene.sfx`。
- **小工厂函数**：例如“花字工厂”一次生成三层字，“逐字变换函数”算每个字在时间 t 的缩放、位移、旋转，“贴纸拍下函数”返回缩放、旋转、抬高和不透明度，相机是一组带运动类型（飞行 / 漂移 / 拉远）的关键帧。我们把这些拆成了 React 组件，接口统一成 `f`（场景帧）+ `at`（卡点帧）。
- **更新函数列表**：每个元素注册一个 `t => 更新样式` 的函数，渲染时依次调用。Remotion 里组件本身就是这个函数，不需要这一层。

### 八、拆解：提示词写法

每份风格提示词由“通用部分 + 风格专属四段”组成：

1. **角色和标准**：“你是这支片子的导演、动效设计、工程师和音效师”，给出标杆（Buck、ManvsMachine、Apple 发布会动效、抖音 / B 站头部设计账号），并说明“像模板就是失败”。
2. **Style**：中英文风格名。
3. **Output（固定）**：分辨率、帧率、精确时长、编码、响度（−14 LUFS）、真峰值。
4. **Suggested technical route**：建议的实现路线，并允许“有更好的办法可以换，但要说明理由”。
5. **Creative seed**：一句话片名，**按秒写节拍**（钩子 → 升级 → 高潮 → 结尾），3–6 个具体色值，字体气质，音乐和关键音效。后面跟一句“你可以改创意，但结果必须是这种风格一眼能认出的标准形态”。
6. **Signature features**：这种风格的来源和用途，视觉特征，关键技法。**要写成可检验的**：写“overshoot 用 `cubic-bezier(0.34,1.56,0.64,1)`，错峰 2–4 帧”，不写“动效要有弹性”。
7. **How to work**：先写创意和节拍表 → 先做 6–10 张关键静帧并自己看 → 再做动效，逐帧看最快的动作 → 做声音并对齐 → 全尺寸渲染并检查规格 → 写一份诚实的自评。
8. **Rules / Craft checklist / 自评打分 / Deliver**：确定性渲染、素材许可、中文要地道；评审清单；从 7 个维度给自己打 1–10 分，最低的先改；交付成片和一份短报告。

外加一个独立评审流程（`rubric.md`）：另开一个 AI 会话当评委，每 0.5 秒抽一帧拼成联系表，看最快的动作和高光，全尺寸看细节；7 个维度严格打分（5 分 = 学生作业，6 分 = 模板水平）；给 5–10 条按影响排序的修改，每条带时间码、问题、原因、具体做法（曲线、帧数、像素、颜色），并且至少一条是提升惊艳度的；然后回到制作会话按意见改，改两轮。

**我们怎么用**（不照抄英文提示词，按本项目改写）：

- 分镜简报里写**签名动作**时用数字：“标题逐字弹出，2 帧错开，第 8 帧落定”“第 3.7 秒锁定框收到 Key 上，晚 3 帧砸下爆炸框”，不写“标题要有动感”。
- 钩子、升级、高光、结尾按秒写进分镜，高光放在 60–75 % 处。
- 出片后可以加一轮**独立评审**：另开会话，用下面这段改写过的评审提示词，评委的维度换成本项目的优先级。

```text
你是短视频评审，没有参与制作这条片子，请严格、具体地挑问题。
片子：<douyin/<id>/video.mp4>；简报：<tutorials/<id>.storyboard.md 的 ## 简报>。
1. 每 0.5 秒抽一帧做联系表，另看 0、1、3 秒和高光时刻的全尺寸帧，再看缩到 360 px 宽的样子。
2. 按 1–10 分打分（5 = 能看，6 = 模板水平，8 = 头部账号水平）：
   钩子（前 3 秒有没有说出、给出最有意思的东西）、留人（每 2–3 秒有没有新东西，有没有死帧）、
   手机可读（字号、对比度、平台界面遮挡）、忠实（数字和说法能不能在素材里找到出处）、
   动效（缓动、错开、卡点、反应时机）、声音（口播清楚、底乐不抢、音效卡在接触帧上）。
3. 给 5–10 条修改，按对完播率的影响排序；每条写时间码、看到的问题、为什么重要、具体做法（帧数、像素、颜色、组件）。
   至少一条是让钩子或高光更强的。
4. 单独列出严重问题：编造的事实或数字、读不清的字、缺字方框、被平台界面挡住的信息。
```

### 九、15 种风格：用什么、不用什么、为什么

| # | 风格 | 结论 | 拿什么 | 不拿什么、为什么 |
| --- | --- | --- | --- | --- |
| 19 | 粗描边贴纸人科普（回形针） | **主要参考** | 贴纸化素材（统一白描边）、大画布一镜到底、图表生长、数字滚动、每句一个新元素、克制配色 | 对方的超大画布是给 16:9 10 秒片子设计的；竖屏上左右飞会撞按钮列，所以只上下飞。按相机速度做运动模糊太费渲染时间，默认不做 |
| 18 | 综艺花字 | 部分 | 三层描边字、弹出曲线、逐字错开、反应晚 2–3 帧、爆炸框 | 汗滴、“绝绝子”式网络梗、萌宠综艺腔：和 AI 新闻、安全类题材的可信度不合；跑动字幕不能弹、不能摆（要读）；一屏多个花字会抢口播 |
| 22 | 赛博 HUD | 部分 | 锁定框、数字跳变后落定、打字机、整屏翻成警报色 | 满屏等宽小字数据流：缩到手机上读不清，装饰小字又不许带信息，只剩噪音；色差、扫描线、频繁故障伤可读性，也让 H.264 码率暴涨 |
| 01 | 扁平矢量 | 部分 | 弹性曲线 `(0.34,1.56,0.64,1)`、错开 2–4 帧、同一时刻一个主角、色块擦除转场 | 几何角色绑骨骼：每条片子都要重新做，成本高，又不带信息；5–6 色色板违反 A/B 两色规矩 |
| 02 | 线描 | 部分 | 描线动画和描线曲线，用在引线、箭头、下划线、路线上 | “一笔画”叙事：节奏慢、奢侈品气质、信息密度太低 |
| 09 | 包豪斯几何 | 部分 | 动作卡在节拍上、落点对齐网格；表格、矩阵这类东西用“无过冲、机械感”的动法 | 竖排拉丁字海报排版不适合中文；全片禁用过冲和我们其他元素的弹性冲突，只局部用 |
| 12 | 极光玻璃 | 部分 | 玻璃卡片配方（背景模糊 + 5–10 % 白 + 1 px 高光边 + 大圆角）、邻近色、渐变加噪点 | “慢、透、呼吸感”的节奏和“每 2–3 秒一个变化”正相反；`backdrop-filter` 渲染很慢；低对比配色在手机上读不清 |
| 08 | 形状变形 | 以后再说 | “A → 圆 → B”两段式变形，概念转换时可用 | 要做顶点匹配插值才不打结，需要新依赖（flubber 一类）；这次不加依赖，等某条片子真的需要再做 |
| 03 | 等轴测 2.5D | 谨慎 | 搭建顺序：底面落位 → 立面拉起 → 顶面晚 2–3 帧盖上，用在架构图生长上 | 每条片子都要搭一个小世界，成本高；等轴测平面上的小字在手机上读不清 |
| 05 | 逐帧手绘 / 线条呼吸 | 只用在装饰上 | 装饰物（爆炸框、手绘圈）的轮廓每 2–4 帧重画一次 | 文字和界面上做 boil 会抖、难读；“一拍二”（12 fps）让软件演示看起来像卡顿 |
| 04 | 3D 渲染 | 不用 | — | 要 Blender 管线和 GPU，云容器里渲不动；产品广告的审美，不带信息；24 fps 浅景深和我们 30 fps 的利落感冲突 |
| 06 | 拼贴 | 不用 | — | 老照片、报纸素材的版权风险高；定格抖动（6–12 fps、±2 px）放在字上难读；超现实调性削弱新闻的可信度 |
| 07 | 液态 | 不用 | — | WebGL 元球很重；一次液态转场要 1–2 秒、不带任何信息 |
| 10 | 合成波 / VHS | 不用 | — | 扫描线、RGB 分离、故意掉帧都伤可读性，而且是压缩的天敌（噪点和细横线会被压成色块）；怀旧调性和 AI 新闻不搭 |
| 20 | 像素 | 不用 | — | 低分辨率下中文笔画糊成一团；8–12 fps 的阶梯动画让信息变化看着卡 |

另外不拿的东西：

- **10 秒、无口播的形式**：我们靠口播传信息，画面服务口播。
- **代码合成音乐**（`mgaudio` 和乐器采样库）：我们已有底乐和真实录音音效（`public/audio/sfx/`），够用；以后真需要合成音乐再单独评估。
- **“冲奖”的评分目标**：我们的目标是完播和看懂，评审维度已经按本项目优先级改写（见第八节）。
- **网页 `renderAt(t)` 渲染器**：我们在 Remotion 上，原理一样，不需要第二套渲染器。

### 十、新增组件（`src/components/`）

用法、参数和例子见 [src/components/README.md](../src/components/README.md)。

| 组件 | 学自 | 什么时候用 |
| --- | --- | --- |
| `curves.ts`（`cubicBezier`、`curve.*`、`popScale`、`popOut`、`holdWiggle`、`wobble`） | 各片的签名曲线 | 写动效时直接点名曲线，不凭手感调 |
| `KineticTitle` | 综艺花字 | 钩子标题、章节标题；`look="hanazi"` 用在每个场景最多一个的情绪关键词上 |
| `BurstCallout` | 综艺花字 + 手绘逐帧 | 一个场景里唯一的“！”时刻：警告、反转、惊人的数字 |
| `LockOn` | 赛博 HUD | 在一屏东西里指出“就是这个”：一个文件、一行日志、一个单元格 |
| `ScrambleText` / `CountUp` / `countValue` | 赛博 HUD、回形针 | 值被读取、解密、泄露（跳变）；口播说到的数字（滚动到真实值） |
| `StickerSlap` | 回形针、拼贴 | 截图、产品图、关键卡片进场；统一描边让不同来源的素材看起来是一套 |
| `CameraRig` / `camAt` | 回形针 | 同一话题的几个信息点放在一张画布上，用相机飞过去，代替硬切 |
| `DrawPath` | 线描、回形针 | 引线、箭头、下划线、路线 |
| `GrowBars` | 回形针 | 2–5 个数字的对比（跑分、价格、数量），按比例生长、数字同步滚动 |

所有组件和 `src/fx` 一样，是场景帧 `f` 的纯函数。数据类组件（`CountUp`、`GrowBars`）不过冲，只显示素材里有的数字。

**默认偏克制**（2026-10-22 复盘后调过）：标题落定后不摆（`wiggle = 0`），爆炸框轮廓不“呼吸”（`boil = 0`）；轻松题材再手动打开。这些组件只给一个场景里最要紧的那一下用，“响”的动作每个场景最多一个（速查页 §六“画面减法”）。

### 十一、下一条片子的落地清单

1. 分镜简报里的钩子画面写成数字：第 0 帧有什么（`KineticTitle` 的 `at` 设成负数，让标题第 0 帧已经落定），第几帧出现第一个变化。
2. 每句口播对应一个新视觉元素；有数字的句子用 `CountUp` / `GrowBars`，有“就是它”的句子用 `LockOn`。
3. 每个场景最多一个高光（`BurstCallout` 或花字关键词），放在场景后半；反应晚 2–3 帧。
4. 同一话题的连续信息点优先考虑 `CameraRig` 一镜到底，竖屏上下飞。
5. 截图和外部素材用 `StickerSlap` 统一描边；外部素材的署名照旧放在贴纸外面。
6. 出片后按第八节的评审提示词另开会话评一轮，再按意见改。

### 十二、为什么是“重写”而不是“搬运”

- 对方是手写网页 + 自研渲染器，代码直接依赖 DOM 操作和全局时间轴，搬不进 Remotion 的 React 组件结构；硬搬还会带进我们用不上的依赖（d3、topojson、Three.js）。
- 对方的参数是给 10 秒风格片调的，我们要按竖屏、口播、手机可读重新定：例如数据不过冲、字幕不弹不摆、反应晚 2–3 帧而信息卡在字上。
- 许可上，MIT 允许复制，但第三方素材各有许可，而且用户要求“只参考做法、代码自己写”。所以本仓库里没有对方的任何文件，只有这份笔记里注明出处的数字和做法。
