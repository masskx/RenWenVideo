# 抖音技巧：开头、中段、结尾、发布

> 2026-10-26 用户：“整体质量，包括钩子和结尾，还能更好；帮我学一些专门针对抖音的技巧。”这一页把**我们自己的后台数据**（[数据复盘-2026-10-26.md](数据复盘-2026-10-26.md)，15 支片）和**公开的运营经验**放在一起。外部经验大多来自运营博客，平台没有公布算法，所以每条都标了依据：**[数据]** = 我们自己量到的；**[经验]** = 多个来源的共识，没有官方数据，当假设用、拿我们的数据去验。第一句和前 10 秒的细节在 [hooks.md](hooks.md)，这页不重复。

## 〇、抖音怎么看一条视频（后台那几个数）

| 指标 | 意思 | 我们的中位数 | 目标 | 低了先查哪 |
|---|---|---|---|---|
| 2s 跳出率 | 2 秒内划走的比例 | 36 % | < 30 % | 第 0 帧和第一句（2 秒只够看清一个画面、听半句话）[数据][经验] |
| 5s 完播率 | 看满 5 秒的比例 | 39 % | > 50 %（我们最好的 55 %） | 第一句说完后，第二句有没有接上一个新东西 [数据] |
| 平均播放时长 | | 9.4 秒 | > 15 秒 | 中段：每 2–3 秒有没有新东西，有没有“二次钩子”[数据] |
| 完播率 | 看完的比例 | 9 %（37–54 秒快讯）/ 1 %（85 秒以上） | > 15 % | 片长、结尾有没有拖 [数据] |
| 分享 / 收藏 / 评论 | | 分享和涨粉几乎全来自 php2shell；评论几乎为 0 | 每支至少设计一个 | 结尾（§三） [数据] |

- 外部给的“优秀线”互相矛盾（完播率 10 % 和 60 % 都有人说），**只跟我们自己近期的中位数比**：新片要比上表好。[经验]
- 平台没有公开权重；公开说法一致的只有方向：前几秒留住人、看得久、看完、有互动的片子会被推给更多人。[经验]

## 一、开头（0–3 秒）：三层同时到

第 0 帧到第 1 秒，三样东西同时到位，缺一样就会有人划走：

1. **画面**：主体已经在、已经在动（不是淡入、不是 logo、不是标题卡）。最好是“结果”本身：龙、打实的那一脚、漏洞告警。[数据：2s 跳出最低的 kimi 25.8 %、sweety 27.6 % 都是真东西在动]
2. **大字**：一行能静音看懂的字——那个数字或那件事（≥ 100 px），不是频道名。[经验]
3. **声音**：第一句口播 0.3–0.5 秒内开口；开头一个短促的音效（敲击、警报、快门）帮着“醒耳朵”。[经验]

开法见 [hooks.md](hooks.md) §一。补两条抖音常见、我们还没用过的：

- **结果先放，再倒回去**：先给 1 秒最终结果（成片、数字、反转后的状态），再说“怎么来的”。[经验]
- **跟观众直接说话（打破第四堵墙）**：「先别划，你仓库里可能也有这个分支」——只在和观众真有关时用。[经验]

## 二、中段：给答案，但留一个“为什么 / 怎么办”

- **前 10 秒给“是什么”（数字、事实），把“为什么”或“你该怎么办”留到后面**——这就是“开环”：观众知道了结论，但还差一块。[经验；和 hooks.md §三 的“10 秒内给核心数字”不冲突]
- **每 2–3 秒一个新东西**（新数字、新画面、新对比），单个画面不超过 8–10 秒。[经验][速查 §三]
- **15–20 秒左右放一个“二次钩子”**：平均看 9–15 秒就走，这里要再拉一次——「但这还不是最狠的」「更麻烦的是……」，后面接全片第二大的东西。[数据：平均看 6–16 秒][经验]
- **别解释过头**：名词解释、背景、出处放上屏小字，口播只讲发生了什么。中段掉人的常见原因是讲得太多、答案来得太慢。[经验]

## 三、结尾：最后一句一说完就结束

抖音的“完播”是看到最后一帧。口播停了画面还在，人就划走了，这条就不算看完。[经验]

**硬规矩**

- **最后一句说完，0.5–1 秒内结束**（配置里最后一个场景 `tailMs` ≤ 1000）。“高潮多停 2 秒”放在**最后一句之前**（招牌镜头那里），不放在片尾。`brief.mjs` 提醒。[经验；我们最近几支片尾停了 1.4–2.3 秒，要改；php2shell 停了 1.4 秒照样爆，所以这条是假设，下几支验证]
- **最后一帧尽量能接回第 0 帧**（同一个物件、同一个构图），自动重播时像没断开，会多出一次播放。[经验]
- **不喊“关注 / 点赞 / 收藏 / 评论区扣 1”**：平台视为低质或引流，观众也会在这里划走（[平台与合规.md](平台与合规.md) §三）。`brief.mjs` 判不过。

**五种结尾，按题选一种**（分镜「结尾台词」后面写明是哪一种）：

| 类型 | 什么时候用 | 我们的例子 |
|---|---|---|
| 1. **一个马上能做的动作** | 风险、安全、隐私——和观众有关的题 | php2shell「补丁打上，才算真的过夜」：分享 371、涨粉 42 [数据] |
| 2. **回扣开头，答上开环** | 开头抛了问题 / 反常 | late-night-emo 回到那张卡片；claude-georgia-paywall「麻烦不在它拿了什么，在没人让它拿」 |
| 3. **一句翻转的判断** | 新闻、研究 | deepseek-identity「模型说自己是谁，证明不了它是怎么来的」 |
| 4. **让人站队的问题** | 观众有立场、或有自己的经历可说 | deepseek-vs-opus55「你缺的是时间，还是钱？」——但评论 0：问题要问到**每个人都有经历**的点上，问“选哪个”不如问“你遇到过吗”[数据][经验] |
| 5. **下一集的钩子** | 做系列时 | 「下一支：它是怎么拿到 token 的」——只在下一支真的会做时用 [经验] |

## 四、发出去以后

- **标题 = 第一句的书面版**：一件具体的事 + 数字 / 时刻（[hooks.md](hooks.md) §五）。描述第一行重复核心事实，带 2–3 个能被搜到的词（产品名、事件名）；话题 3–5 个：1 个大的（#AI工具）+ 2–3 个具体的（#Claude #GitHub）。[经验]
- **封面 = 第 0 帧那一张**：主页九宫格里封面就是标题（[封面.md](封面.md)）。[经验]
- **评论区**：发布后作者自己先发一条评论——补一个片子里放不下的事实，或者问一个“你遇到过吗”；前一两个小时回复评论。作者回复也会让评论区更活。[经验]
- **每周导入后台数据**（`scripts/stats/douyin-export.py`），一次只改一个变量（开头类型、片长、结尾类型），看它动了哪个数。[数据]

## 五、每支片发之前问自己的六个问题

1. 静音看第 0 帧，知道这条讲什么吗？
2. 第一句是不是一件具体的事 + 数字 / 时刻？（不是日期、问候、“这条视频”）
3. 核心数字在 10 秒内说了吗？“为什么 / 怎么办”有没有留到后面？
4. 15–20 秒有没有第二个钩子？
5. 结尾是五种里的哪一种？最后一句说完 1 秒内结束了吗？最后一帧能接回第一帧吗？
6. 标题、封面、第一句是不是同一件事？
