# 动效与画面变化

> [讲解动画规则.md](讲解动画规则.md) 管“看得清、卡得准”，这份管“画面一直有新东西”，[导演层.md](archive/导演层.md) 管“观感”：主次、错相、物理、光、声和禁止项。三份冲突时以导演层为准——尤其是本文第四节的“每句换构图”和“整幅震屏”已经不再是默认做法。写分镜时照第一节给每个镜头列变化清单，挑转场查第三节，写代码时调 `src/fx`（第八节），出片后按第七节自查。
> 改编自 [dashi-animationstyle](https://github.com/chuspeeism/dashi-animationstyle) 的 `knowledge/动效和画面变化.md`（MIT，© 2026 Dashi AI Lab）。原作者做过一次盲测，得出一个结论：观众觉得“更丰富”的版本，每 2–3 秒都有看得见的新东西，背景也一直在动。

## 一、每个镜头写清四件事

| 环节 | 是什么 | 时长、幅度 |
| --- | --- | --- |
| 进场 | 怎么出现：弹出、掉落、滑入、描出、拍上 | 0.2–0.5 秒，比关键词早 0.03–0.1 秒 |
| 主动作 | 这个镜头要讲的那件事怎么演：变形、移动、填色、打勾、盖章、数字滚动 | 跟着口播走，卡在关键词上 |
| 次要动作 | 讲的时候一直在动的小东西：呼吸、飘动、闪烁、粒子、光标、慢推 | 持续整个镜头；位移 2–6 px、缩放 1–3%、旋转 1–2°，周期 1.5–4 秒 |
| 出场 / 转场 | 怎么离开、怎么换到下一个：推走、擦掉、翻页、故障 | 0.3–0.7 秒 |

- 写不出主动作的镜头，就是只有字的镜头，要重新想画面。
- 次要动作不能抢戏：一屏最多 2 种，幅度小、周期慢，离正在讲的东西远一点。
- 讲完停住的那几秒最容易“死”：给主体加一个呼吸（`sway`），或者慢推（`slowPush`）；更好的办法是让次主体、影子、背景按错相继续回应（导演层第三节），或者让主体变形成下一个状态。
- 东西能留就留：上一镜的主角缩小挪到角上，陪着下一镜，比清空重来更连贯，也多一次变化。

**本项目的落地**：长文讲解在 `explainers/<id>.json` 的每个场景里用 `stamp: {line, phrase, text}` 写主动作；`build-explainer.mjs` 会算出关键词被念到的时刻，印章在那一刻砸下并震屏。教程的主动作写在每期的 `src/tutorial/scenes/<id>.tsx` 里，用旁白的 `{a}` 标记卡点。

## 二、多久要有一次看得见的新变化

| 多久 | 要什么 |
| --- | --- |
| 每 2–3 秒 | 一个看得见的新变化：新东西进场，变形、换色、换位置，镜头推近或拉开 |
| 每 3–5 秒 | 一次大变化：换镜头、换版面 |
| 一直 | 至少一样东西在动，静止不超过 2 秒 |
| 开头 3 秒 | 最密：1–1.5 秒一个变化 |
| 讲原理 | 一张图可以撑 10–20 秒，但图里每 2–3 秒要亮起新的一步 |

“看得见”是指缩到手机上也看得出：小于画面 10% 的变化只算次要动作，不算新变化。

**量化检查**：`node scripts/qa/richness.mjs douyin/<id>/video.mp4`。每 2.5 秒取一格，算相邻两格的平均像素差（0–255，字幕带不算）。

- 判“过”：平均 ≥ 10，并且没有“几乎没变”（< 4）的格；静止超过 2 秒另外提醒。
- 本项目实测（2026-10-15，加入 `src/fx` 前 → 后）：

| 视频 | 平均变化 | 几乎没变的格 | 在动的帧 | 最长静止 |
| --- | --- | --- | --- | --- |
| ai-era-11-rules（长文讲解） | 12.7 → 17.3 | 7 → 0 | 64% → 100% | 7.8 s → 0 |
| rea-quickstart（教程） | 4.4 → 12.8 | 47 → 0 | 28% → 90% | 4.9 s → 0.8 s |
| ochiai-claude-code（教程） | 3.4 → 10.6 | 65 → 0 | 14% → 86% | 6.7 s → 1.6 s |
| marketing-engineer（长文讲解） | 10.2 → 16.4 | 25 → 0 | 35% → 99% | 14.6 s → 0.1 s |

## 三、转场要换着用

- 全片至少 3 种转场，同一种不要连着用 3 次。换话题（大段落）用大转场：横扫、翻页、圆形遮罩；段内换镜头用小转场：推移、故障、上推。
- 转场 0.3–0.7 秒，卡在句界上，画面被盖住的那一刻正好换内容。白闪、强故障一秒内不超过 3 次。
- 转场要像这种材质会发生的事：纸会掉、会撕、会翻；黑板会被擦；屏幕会故障、会关机；报纸会翻版、会推移。

| 风格 | 适合的转场 |
| --- | --- |
| 深色科技（本项目两条流水线） | 色块横扫、圆形遮罩、推移、故障（要克制，0.14 秒左右）、光速推移 |
| 剪纸、手账 | 纸片掉落盖满再撕走、翻页、彩纸条横扫、定格硬切 + 抖一下 |
| 粉笔黑板、白板 | 黑板擦擦掉、横移到下一块板、推近再拉开 |
| 手绘笔记 | 往下滚动、卷角翻页、橡皮擦掉、推近穿过去 |
| 霓虹、蓝图 | 故障撕裂、CRT 关机、扫描线扫过、灯管断电再通电 |
| 复古报刊、杂志 | 整版推移、翻报纸、印章盖下后切版 |
| 扁平流程图 | 沿流程横移、形状变成下一个形状、圆形遮罩、色块横扫 |

**本项目的落地**：`planCuts(times, isBig)` 会自动给每个切点分配转场：大切点在 `BIG_KINDS`（横扫、翻页、圆形遮罩）里轮换，小切点在 `SMALL_KINDS`（推移、故障、上推）里轮换。长文讲解里，场景之间是大切点，同一场景里换图是小切点，小切点只作用在背景上，章节标题不跟着动。教程里步骤号变化算大切点，开场还有一次圆形遮罩揭开。

## 四、分层和镜头推拉

- 至少分两层，层和层动的速度不同（视差）：背景只慢慢动，中景是讲的东西，前景是粒子、光带。本项目用 `Particles`（光点往上飘）和 `LightSweep`（斜光带扫过）做前景层。
- 讲的时候慢推：每秒放大 1–1.5%，最多推 5 秒（`slowPush`）。
- ~~按字幕节拍推拉~~（**已不是默认做法**，见导演层第八节）：每句字幕整幅换一次构图，没有理由的整屏推拉正是“AI 味”的来源之一。旧片保留；新片在教程配置里写 `look.tour: false`，变化靠主体过程、次主体回应和有理由的相机（`follow`）。下面两条只在长文讲解的满屏配图上还可以用，且要配合前景层的独立运动：
  - `beatZoom`：推近和拉开交替。适合满屏照片的背景（长文讲解）。
  - `beatTour`：在 4 个不同构图之间轮转，不回到原位。适合深色舞台上的小面板（教程）。只用 `beatZoom` 时，教程的平均变化只有 7.2，换成 `beatTour` 后到了 10.5。
- 震屏：盖章、砸下、撞击的那一下，0.15–0.25 秒、8–16 px、逐渐衰减；一段最多两三次（`shake`）。**新规则：冲击分层错相传播**——被撞的东西幅度最大，周围的小一些、晚 2–4 帧，背景只轻微回应；不要整屏一起抖（导演层第六节）。
- 镜头运动用 `ease.inOutCubic`，不用匀速。
- 浅色东西在浅底上动，丰富度检查几乎量不出来：浅底风格要靠镜头推拉，或深色、饱和色的东西移动来制造变化。

## 五、动画原则（挑讲解动画用得上的 6 条）

| 原则 | 意思 | 代码 |
| --- | --- | --- |
| 预备 | 大动作之前先往反方向来一点 | `anticipate(p)`：先退 8%，再冲出去 |
| 跟随和重叠 | 停下时冲过头一点再回来；附属的东西晚几帧才停 | `ease.outBack(p, 1.2–1.7)`；附属物晚 0.07–0.13 秒 |
| 缓入缓出 | 起步慢、停下慢、中间快 | 进场 `outCubic`，出场 `inCubic`，镜头 `inOutCubic` |
| 弧线 | 东西沿弧线走，不走直线 | 二次贝塞尔，中间控制点抬高 80–200 px |
| 次要动作 | 主动作之外的小动作，不能抢主动作 | `sway`、`blink`、`Particles` |
| 节奏 | 快 = 轻，慢 = 重 | 轻东西 0.2–0.3 秒到位；盖章 0.12 秒砸下再加震屏（`Stamp` + `shake`） |

- `outBack` 的 s 超过 2 就会像果冻，只给轻的小东西用。
- 定格一拍二（每秒 12–15 张，`jitter`）适合手工、纸、黏土类风格；屏幕、科技类别用，会显得卡。

## 六、好用的手法（来自原项目的盲测）

| 手法 | 怎么做 | 适合 |
| --- | --- | --- |
| 印章盖下 | 1.9 倍 → 1 倍，0.12 秒，加震屏（`Stamp`） | 各种风格的结论、关键词 |
| 流式打字 | 显示字数 = 进度 × 总字数，末尾一个闪烁光标（`typed` + `blink`） | 科技、聊天类内容 |
| 光点粒子 | 往上飘、会闪烁的柔光点，避开字幕带（`Particles kind="glow"`） | 深色科技、霓虹 |
| 停住后轻轻摇 | 旋转 `sin(1.7t)` 度，上下 `3·sin(2.3t)` px（`sway`） | 卡片、纸片、贴纸 |
| 纸片掉落拼标题 | 每块从上方掉下，`outBack(1.2)`，一块比一块晚 0.08–0.12 秒 | 剪纸、手账 |
| 灯管字逐字通电 | 先画暗轮廓，每个字被念到时乱闪 0.25–0.3 秒，然后常亮 | 霓虹、片头 |
| 雨夜城市视差 | 楼宇剪影每秒左移 14 px，雨丝每秒落 900–1500 px（`Particles kind="rain"`） | 霓虹、黑底科技 |
| 推近再拉开 | 推近 1.15–1.25 倍看刚写出的东西，到关键词再拉开看全貌 | 板书、笔记、报刊 |

## 七、丰富度自查表

**写分镜时**
- [ ] 每个镜头的进场、主动作、次要动作、转场都写了
- [ ] 转场至少 3 种，同一种没有连着用 3 次；大段落用大转场
- [ ] 开头 3 秒至少有 2 个变化

**出静帧时**（`--still` 抽 3 张：开头、中段、结尾；再按 [审美参考库.md](审美参考库.md) 第三节做一次减法自查）
- [ ] 至少两层：背景有东西，不是纯色底上摆字
- [ ] 有次要动作，但没抢戏：缩到 360 宽（`scan.mjs --phone`）字照样一眼能读
- [ ] 这一帧里有正在发生的动作，不是全部摆好在等着
- [ ] 三张之间的版面、主体大小和位置明显不一样

**出片后**
- [ ] `node scripts/qa/richness.mjs <video.mp4>` 判“过”
- [ ] 没有静止超过 2 秒的段
- [ ] `node scripts/qa/scan.mjs <video.mp4>` 的扫片里，转场确实有 3 种以上，镜头交界处没有截断、叠字、空白；可疑的切点用 `--around=秒` 细看
- [ ] 文件小于 100 MB（动得越多，码率越高：长文讲解用 `--crf=25` 约 50 MB；教程用 `--crf=23` 约 65 MB）

## 八、`src/fx` 速查

| 要什么 | 调用 | 说明 |
| --- | --- | --- |
| 切点转场 | `<CutStage t cuts width height colors fill paper>{画面}</CutStage>` | 只包画面，不包字幕、页眉和音频；可以嵌套，大切点包整个画面，小切点只包背景 |
| 分配转场 | `planCuts(times, (i) => isBig)` | 返回 `[{at, kind}]` |
| 节拍推拉 | `beatZoom(t, beats)` / `beatTour(t, beats)` | `beats` = 每句字幕的开始秒数；返回 `{s, dx, dy}` |
| 震屏 | `shake(t, hits)` | `hits` = 印章、撞击的时刻；返回 `{dx, dy}`，套在整个画面外面 |
| 慢推 | `slowPush(t, t0)` | 返回缩放倍数 |
| 进场 | `enter(t, at)`、`anticipate(p)`、`ease.*`、`prog(t, t0, d)` | `enter` 默认提前 0.06 秒、0.35 秒、带一点过冲 |
| 次要动作 | `sway(t, ph)`、`blink(t)`、`jitter(t, i)` | 返回数值，自己乘到 transform 或 opacity 上 |
| 粒子 | `<Particles t width height kind n colors area />` | `kind`：`glow`、`rain`、`confetti`、`dust`；用 `area` 避开字幕带 |
| 光带 | `<LightSweep t period opacity />` | 前景层 |
| 印章 | `<Stamp t at text color size />` | 配合 `shake(t, [at])` |
| 关键词上色 | `<KeywordText text keywords />` | 精确匹配，长的优先；A/B 两个核心名词用固定颜色 |
| 打字 | `typed(text, t, t0, cps)` | 配 `blink` 画光标 |
| 随机 | `hash(n)` | 带种子；不要用 `Math.random()` |
| 弹簧（闭式解） | `springStep(t, t0, o)`、`springTrack(t, from, keys, o)`、`twoEdge(...)` | 一个值多次换目标 = 每次叠加一个弹簧；两条边不同刚度，自然拉伸（导演层第四节） |
| 抛出、下落、弹跳 | `toss(t, o)`、`drop(t, o)` | 返回位置、速度、接触时刻；接触时刻同时给音效用 |
| 挤压拉伸、冲量 | `squash(vx, vy)`、`impulse(t, at, o)` | 形变来自速度和冲量，体积守恒 |
| 错相、传递 | `PHASE`、`lagged(t, layer)`、`ripple(t, at, i, o)` | 各层延迟帧数；一排元素依次收到冲击 |
| 相机跟随 | `follow(t, keys, o)`；画面组件的静态属性 `camera(cue, dur)` → `{at, x, y, z}` | 临界阻尼，晚主体 4–6 帧，不过冲；`TutorialVideo` 在 `look.tour: false` 时按关键帧推拉，横向不切字 |
| HUD 层 | 画面组件静态属性 `hud = true`；组件收到 `layer: 'stage' \| 'hud'`，用 `layers(layer)`（`src/tutorial/paper.tsx`）分开画 | 标题、大数字放 HUD：只随相机缩放到 1.05 倍、不往上移，不会被裁半行；画面放 stage，随相机推拉 |
| 光、接触影、运动模糊 | `KEY_LIGHT`、`matte(color)`、`<ContactShadow>`、`<Smear>` | 主光左上；离地越高影子越小越淡；快速运动拖残影 |
| 音效 | 画面组件的静态属性 `sfx(cue, dur)` → `{at, kind, gain}` | `TutorialVideo` 混音；音效库 `scripts/generate-sfx.py` |

`t` 一律用秒，由 `useCurrentFrame() / fps` 算出来，画面只由 `t` 决定。
