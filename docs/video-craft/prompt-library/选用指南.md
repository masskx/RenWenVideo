# 选用指南：按脚本挑提示词库里的参考

> 可选参考。优先级照旧：**钩子 → 留人 → 手机看得清 → 忠于脚本和素材 → 打磨**（[quick-reference.md](../quick-reference.md)）。库里的东西只在它能帮前面几条时才用；画面基准是 cinema 风格（速查页 §六“高级感”，样片 `tutorials/claude-proactive-agent-cinema`、`tutorials/litellm-pypi-poison-cinema`），参考库是在这套样子上**换招**，不是每期换一整套风格；借来的招也要守“一个主角、金色唯一强调色、不加装饰”。
>
> 下面的 id 都能直接看全文：`node scripts/prompts/find.mjs --show=<id>`。

## 一、什么时候查

- **计划阶段**：读完脚本和素材、定了钩子以后，排场景和关键镜头之前。按 §二 的脚本类型找 1–2 条参考。
- **片子平、没有记忆点**：lemo 每种风格的 §8「Native moves」（原生招式）是按“适合什么内容”写的，挑一招放在高潮。
- **脚本讲的就是这些仓库，或者讲“用 AI 写代码做视频”**：库里的文件就是素材，见 §五。
- **不用查**：素材本身就够撑满（有好录屏、好案例片），基准风格已经合适的时候。

## 三、改写对照：原提示词 → 本仓库

| 原提示词里写的 | 在本仓库改成 |
|---|---|
| 1920×1080、24 fps、10 秒或 30–60 秒 | 1080×1920、30 fps；默认 ≤ 60 秒；构图按竖屏重排，要紧内容避开右侧按钮列和底部文案区（[讲解动画规则.md](../讲解动画规则.md)） |
| 自己写 HTML/Canvas/Three.js，`renderAt(t)` 逐帧截图 | Remotion 组件，`useCurrentFrame()`；“每一帧只由时间决定、帧之间不存状态”这条原则完全一样 |
| edge-tts、ElevenLabs、Kokoro 或“最好的 TTS” | 只用用户本人的复刻音色（豆包），逐字时间戳驱动字幕和卡点；edge-tts 只在用户同意时作备用 |
| 自己合成配乐、−14 LUFS | 本仓库的底乐和音效库（[音效.md](../音效.md)），响度约 −15 LUFS |
| 英文字幕、或者“不要字”（cab） | 简体中文，字幕 ≥ 60 px、要读的字 ≥ 40 px；cab 的“不要字”不照搬 |
| 虚构品牌、虚构产品、“自由发挥故事” | 用脚本和素材里的真东西；不编事实和数字 |
| “Benchmarks: Buck、Apple keynote……” | 参考只学语法（构图、节奏、镜头、配色逻辑），不在画面上出现别人的名字、界面、字体、logo |
| 提示词里的 Creative seed（故事、片名、文案） | 换成脚本的钩子和看点；保留风格的 Signature features、配色逻辑、原生招式、镜头语法和坑 |
| “先出分镜再写代码” | 本仓库的计划步骤：简报五项 + 场景表，给用户确认后再配音渲染（和原提示词的做法一致） |

## 四、可以直接吸收的做法（按优先级归位）

**钩子**

- 前 3 秒就要有事发生，不要慢慢亮 logo（`lemo/DIRECTOR` §3）。
- 开场三种现成写法（`lemo/dark-keynote` §11）：数字先出、一屏插画面快闪再平静、空网格一格格填满。

**留人**

- **写出每一镜的 reads**（`cab/ANIMATION_GUIDE` §4）：观众这一镜要依次看懂哪几件事。一次只给一件；动作可以快，意义要留时间；先把视线引过去（让它动、变亮、变大）再出重点。场景长短由 reads 决定，不靠凑时长。
- **变速**：快慢交替，至少一次明显加速或减速，给观众一口气（一个长镜头或停顿）；全片一个速度就是失败（`lemo/DIRECTOR` §7）。
- 每期挑**一个原生招式**放在高潮（`lemo/DIRECTOR` §3；招式见各风格 §8）。

**手机上看得清**

- 上屏大字（不是跟着口播走的字幕）入场后的停留时间，可以按 **字数 ÷ 4.5 + 1.5 秒** 估（`lemo/DIRECTOR` §7）；标题卡至少停 4 秒。
- 最常见的失败（`lemo/DIRECTOR` §10）：主体太小、太远或贴边；太暗或同色压同色；字幕挡住主体；转场里有空白帧。关键时刻主体至少占画面高度的 1/3（§8）。

**忠于脚本和素材**

- 讲别人的 AI 视频时，“一次提示”“纯代码”“零素材”“无人修改”是四件互相独立的事，不能拿一件说另一件（`ac55/prompt-playbook.zh-CN` 末节）。作者用了参考图、既有素材、多轮修改或外部视频模型的，照 `ac55/prompt-matrix.zh-CN` 的“应如何描述成果”写；作者自述的耗时和费用写「据 @作者」。
- 讲数据：可以换取景，不能动数字（`lemo/dataviz`）；每个数字记出处（`lemo/archive-lighttable` 的 FACTS.md，对应本仓库分镜的“素材和出处”）。

**打磨**

- 写新风格卡时，特征要能检验：写“overshoot 用 cubic-bezier(0.34,1.56,0.64,1)，错峰 2–4 帧”，不写“动效要有弹性”（`mg15/template`；本仓库模板见 [风格卡模板.md](../风格卡模板.md)）。
- 第二意见：成片后另开一个会话，用 `mg15/rubric` 的评委提示词审片，但把七个评分维度换成本仓库的五级优先级，再按意见改一轮。
- “别又做成样片”：用了某个 lemo 风格，结构、开场、招牌镜头、镜头路线、配乐形状、结尾六项里至少四项要和它的 `…/demo` 不同（`lemo/DIRECTOR` §11）。
- 声音：每个看得见的动作都有声音；高潮或转折前至少两次真正的安静（安静后的第一个声音要是全片最重要的声音之一）；至少两次用声音做转场（下一场的声音先进来，或上一场的声音拖过切点）（`lemo/DIRECTOR` §6，配合 [音效.md](../音效.md)）。
- “模板味”多半来自粒子爆炸、RGB 分离、镜头光晕、霓虹辉光、弹跳缓动（`ovp/README` 写法经验）。本仓库不禁止这些，只在画面显得像模板时拿来对照。

## 五、用一条参考的步骤

1. `find.mjs` 找到候选，`--show` 读全文。lemo 风格先读 §1（是什么、不是什么）、§8（原生招式）、§9（坑）；mg15 读 Creative seed 和 Signature features；opus55 / ovp 看提示词本身和原帖。
2. 只拿用得上的一两招或一个结构，落到具体场景上，不要整套照搬。
3. 按 §三 改写，简报五项照常写。
4. 在分镜里记下用了哪几条（[分镜模板.md](../分镜模板.md) 的“参考提示词”，可选），例如：`lemo/dark-keynote §8 数字乱码落定 → 场景 hook`。
5. **片子讲的就是这些仓库或某条提示词时**：快照里的文件就是素材。原文照引，标「据 @作者」；截图用作者仓库或原帖的真实页面；作者和链接写进发布包 README；帖子里的 star 数是作者发帖时写的，上屏前按当天的数字核对，或者写成“据 @KinGao476942”。
