# 文案：把别人的帖子讲成我们自己的故事

> 2026-10-16 用户定的规矩。以前的做法是“帖子 → 视频”直接转：原文讲什么、按什么顺序讲，视频就跟着念一遍。结果是**没有自己的视角，像在复述别人的帖子**，频道没有自己的节奏和辨识度，长期做不下去。
> 从现在起：**原帖只是素材，视频讲的是我们的故事。** 写分镜之前，先过这份文件。

## 一、两条硬规矩

1. **把帖子的内容变成我们自己的视频故事。** 不照原文的顺序，不照原文的标题，不逐条念要点。先想清楚“这件事里有什么故事”，再从原文里挑能撑起这个故事的材料。
2. **视角要清楚。** 每部片子开写前，必须选定一个视角讲一个话题（一项技术、一个现象、一个技巧），全片不换：

| 视角 | 谁在说话 | 适合什么题材 | 口吻 |
|---|---|---|---|
| **讲述者视角（第一人称）** | 频道主“我”（配音就是用户自己的声音） | 技巧、工具、方法、学习路线、观点 | “我把它拆开看了一遍”“我最认同的一点是……”“如果你也在学……” |
| **第三方视角（旁观者讲故事）** | 一个讲故事的人，不出现“我” | 新闻、现象、某个人 / 公司的经历、行业变化 | “10 月 15 日，得州一处测试场里……”“他被拒之后做的第一件事，是……” |

- 第三方视角讲完故事，**结尾可以由“我”出来说一句判断**（这是唯一允许切换的地方，而且只能在结尾）。
- **第一人称必须真实。** 配音是用户本人的声音，“我”说的经历就是用户的经历：可以说“我读了”“我对照了”“我算了一下”（这些是做片时真做过的事）；**不能编**“我用了三个月”“我上周面试”这类没发生的事。拿不准的，改成第三方视角。

## 二、写之前先填选题卡（写进分镜开头的 `## 选题卡`）

| 项 | 要回答的问题 | 写不出来说明什么 |
|---|---|---|
| 一句话 | 这条片子讲的是什么？（不是原帖标题，是我们的判断） | 还在复述，没有自己的看法 |
| 视角 | 讲述者 / 第三方？为什么选它？ | |
| 主角 | 故事里谁在做事、谁有麻烦？（可以是一个人、一家公司、一项技术，或者观众自己） | 没有主角就只剩要点清单 |
| 冲突 | 主角卡在哪里？什么和预期不一样？观众为什么该在意？ | 没有冲突就没有人看完 |
| 我们的观点 | 至少一条原文**没有**的东西：判断、对比、局限、适合谁不适合谁、换一个角度的解释 | 没有这一条，就是转述 |
| 观众带走 | 看完能做的一件事，或者能回答的一个问题 | |
| 原文用多少 | 从原文里挑哪几块材料？其余的明确删掉 | 什么都想讲，就什么都讲不清 |

## 三、故事怎么搭（≤ 60 秒的口播，结构见 §七）

1. **钩子（前 5 秒）**：一个场景、一句扎心的话、一个反常识的事实、一个观众正在犯的错——**不是**话题名，也不是“今天给大家介绍……”。
2. **主角和冲突**：谁、遇到了什么、为什么难。观众要在这里认出自己。
3. **展开**：知识点按“故事里冒出来的问题”出场，每一段回答上一段留下的问题，而不是“第一、第二、第三”。原文的清单可以保留，但每一项都要挂在故事上。
4. **转折 / 我们的观点**：至少一段是我们自己的东西（见选题卡），口播里要说出来，比如“这份路线我最认同的不是任何一个技术名词，而是……”。
5. **落点**：回到开头的钩子，给一个能带走的结论或问题；结尾可以固定频道自己的收尾句式（等用户定下来再写进这里）。

## 四、写口播的手感

- **说话，不是念稿**：短句，口语，一句话一个意思；能用例子就不用定义；数字只留最有冲击力的一两个。
- **少用原作者的原话**：原文观点要转述成我们的话，引用最多一两句；“某某在帖子里说……”全片出现一次就够（署名放在画面角标和发布包里）。
- **删**：原文 60%–80% 的内容在视频里不出现是正常的。一部片子一条主线。
- **区分事实和观点**：事实要有来源；观点要说成观点（“我觉得”“在我看来”只在讲述者视角里用）。
- **语速跟着写**（`配音.md` §〇·二）：钩子、列举写成短句配快档位；观点、转折那一句单独成句配慢档位。

## 五、自查（写完口播、进分镜之前）

- **换名测试**：把原作者的名字换掉，这段口播还是原帖的复述吗？是的话，重写。
- **观点测试**：把“我们的观点”那一段删掉，片子还成立吗？如果成立，说明观点没长在故事里，太弱。
- **钩子测试**：只听前 5 秒，会不会想听下去？
- **视角测试**：全片是不是同一个视角？第一人称说的事是不是都真的发生过？
- **顺序测试**：段落顺序和原文一模一样？那多半还是在搬运。

## 六、例子：`agent-engineer-roadmap` 改写前后（只改文案，不重做视频）

**改写前（复述型）**：开头交代“Chasen 去面一家公司，没过……他把指南整理公开了：五个阶段……”，之后按原文顺序逐段讲 LLM 基础 → API → Prompt → RAG → Agent → 后端 → 项目推荐 → 交付标准。信息是对的，但每一段都是“原文说了什么”，没有我们自己的判断，换成任何一个转述号来发都一样。

**选题卡（改写后）**

- 一句话：会调模型不等于会做 Agent——一个被面试官点破的工程师，和一份能拿来自测的路线。
- 视角：讲述者（我），对着正在学 Agent 的观众说；Chasen 的经历作为开场故事。
- 主角：先是 Chasen，第二幕起换成观众自己（“你在哪一站”）。
- 冲突：“AI 这块没问题，工程能力不太行”——大多数人学 Agent 学的正是“AI 这块”。
- 我们的观点（原文没有的）：① 五个项目里真正筛人的是第四个——把 Agent 做成别人能跑的服务；② 判断自己学会没有，只看一件事：AI 写完代码后，你能不能亲手跑出一个异常案例并解释它。（都是看完路线后的判断，口播里说成观点。）
- 观众带走：用“输入、输出、成功标准、会在哪失败、失败了怎么办”五个问题，给自己手上的项目打分。
- 原文用多少：面试评价、五个项目和各自的验收标准、上下文窗口和 Agent 循环两个概念；删掉大部分技术名词清单（采样参数、向量库清单、Redis 数据结构……）。

**口播（改写后，节选；`{pace:…}` 是语速档位）**

> 【hook，brisk】“AI 这块没问题，工程能力不太行。”这是一个工程师面试被拒时，听到的原话。如果你最近也在学 Agent，这句话值得你停下来想三秒。
> 【hook 续，slow】{pace:slow}因为它说的，很可能就是你。
> 【story，calm】他叫 Chasen。被拒之后，面试官递给他一份入门指南。我把这份指南从头读到尾，发现它想筛掉的，恰恰是只会调接口的人。
> 【turn，normal】指南把路线拆成五个项目，每个都写了验收标准。前三个你大概都听过：一个 API 练习场，一个能查资料的问答助手，一个简化版的编程 Agent。
> 【view，slow】{pace:slow}但我觉得真正筛人的是第四个：把你的 Agent，做成别人一条命令就能跑起来的服务。
> ……
> 【ending，calm】所以回到那句评价。工程能力到底指什么？我的答案是：AI 帮你写完代码之后，你能不能亲手跑出一个异常案例，并且讲清楚它为什么会失败。{pace:slow}你现在，卡在哪一站？

对比：改写后的开头是一句扎心的话 + 观众自己；知识点变成“前三个你听过，第四个才是坎”；结尾回到开头那句评价，并且给出了我们自己的答案。

## 七、短视频节奏与时长（用户规定，2026-10-17）

用户反馈：已经做的片子**太长、太平、没有短视频的节奏**。从现在起：

### 7.1 时长：默认不超过 60 秒

- **除非用户明确要求，成片 ≤ 60 秒**。`scripts/qa/brief.mjs` 会检查：成片超过 60 秒、或口播字数超过预算（60 秒 ≈ 288 字，按剪气口后约 4.8–5.5 字/秒），直接不过。用户要更长时，在配置里写 `"maxSeconds": 90` 之类。
- **超了就删，不要靠加快语速硬塞**。一部片子一个点：选题卡的“一句话”撑不起的内容全部删掉；例子留一个，数字留一个。
- 场景不超过 8–10 秒（`brief.mjs` 超过 12 秒会提醒）：长场景拆成两个，或者删。

### 7.2 60 秒的结构（参考比例）

| 段落 | 时间 | 要做到 |
|---|---|---|
| 钩子 | 0–3 秒 | 一句话 + 一个画面就让人停下：反常识、冲突、悬念、直接点名观众的痛点。**不要**铺垫、自我介绍、“今天给大家讲……” |
| 承诺 | 3–6 秒 | 告诉观众看完能得到什么（“三十秒讲清楚……”） |
| 展开 | 6–45 秒 | 2–3 个节拍，每个节拍 8–12 秒：问题 → 画面演示 → 一句结论；节拍之间用反问或转折接（“可问题来了——”“结果呢？”） |
| 我们的观点 / 反转 | 45–53 秒 | 一句话的判断，这是全片唯一可以放慢的地方 |
| 收尾 | 53–60 秒 | 回到钩子，给一个能带走的动作；互动问题一句话，不拖 |

### 7.3 口播写给“耳朵”，情绪写进字里

复刻音色对“情绪指令”不太敏感，但会顺着**文字的语义和标点**读出起伏（`配音.md` §〇·三 实测：口语化重写后音高起伏 +27%）。所以：

- **短句**：一句 ≤ 16 字，一口气说完；长句在逗号处拆成两句。`brief.mjs` 发现一句超过 22 字会提醒。
- **每句都有态度**：反问（“你真的看懂了吗？”）、感叹（“这一步最关键！”）、转折（“可问题来了——”）、口头语（“说真的”“结果呢？”“注意！”）。一段里至少有一处情绪的高点和一处落点。
- **直接对“你”说**，少用书面语（“具有”“进行”“相关”“以及”），能用动词不用名词。
- **不用省略号**（会读成长停顿，拖节奏）；要悬念用破折号或干脆断句。
- **节奏要有变化**：连续三句一样长、一样的句式，就改一句。快的地方（列举、过程）连着说，慢的地方（观点）单独成句、前后留白。
- 写完读一遍出声：哪里自己读着都没劲，配出来也没劲。

### 7.4 画面和声音的节奏（配合 `导演层.md`）

- 画面每 1–2 秒有一个新变化（主体动作、景别、高亮、文字），口播的每个重音落在一个卡点上。
- 底乐分段：钩子和反转处抬起、讲解时压低；结尾干净收住，不要长淡出。
- 字幕是“一句一屏”，不超过 13 个字。
