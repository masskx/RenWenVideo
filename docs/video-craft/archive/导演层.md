# 导演层：从“做出来”到“有观感”

> 其他几份文档管“看得清、卡得准、一直有变化”。这一份管**观感**：观众先看哪、什么时刻停、哪次碰撞要有重量、哪里绝对不能发光。写分镜之前先过这一份。
> 来源：观默（X @guanmo_ai）《全网首发！用 Codex 自动生成顶尖动效视频》（2026-09-30，https://x.com/guanmo_ai/status/2105146205915283737 ，含 13 张配图）；twoclipping（X @twoclipping）公开的动效提示词模板（https://x.com/twoclipping/status/2103273003555402193 ）；参考画廊 awesome-ai-motion（https://guanmo-ai.github.io/awesome-ai-motion/ ）。本项目按 9:16、30 fps、口播带节奏的讲解视频重新换算和改写；和旧规则冲突时，**以这份为准**（冲突点见文末）。

## 零、我们的片子为什么一股 AI 味

原文的判断：同一个模型，有人出神作、有人出废片，差别不在“会不会写动画代码”，而在有没有**导演层**——镜头、主次、轨迹、物理、光、声、禁止项、验收标准。缺哪项，代码就退回默认值：**居中大字、霓虹渐变、全体同步淡入**。

成片质量 ≈ **设计判断 × 运动语言 × 素材 × 节拍与声音 × 渲染 × 自检**。有一项接近 0，成片就像“AI 做的 PPT”。

对照本项目已经发布的片子（2026-10-15 自查，以 `ai-agent-team` 为例），每一项都踩了：

| 原文说的默认值 | 我们片子里的样子 | 属于哪一项 |
|---|---|---|
| 全体同步淡入 | 每个元素都用同一个 `usePop` 弹簧、同一个 `Appear` 往上浮 40 px；一镜里十几个东西用同一种方式出现 | 运动语言 |
| 整幅推拉、死轮廓位移 | `beatTour` 每句字幕把整个舞台平移缩放一次，镜头没有理由；`shake` 把整个画面一起抖 | 运动语言、相机 |
| 无理由发光、霓虹渐变 | 卡片 `boxShadow: 0 0 36px 色`、头像光环、青紫渐变标签、背景两团彩色光斑 | 光 |
| 居中大字 + 卡片堆 | 深蓝底上一张张圆角卡片往下排，一屏五六十个字，像 PPT | 设计判断 |
| 颜色太多 | 4 个角色色 + A/B 两色 + 琥珀 + 青 + 红，一屏同时出现 6 种强调色 | 设计判断 |
| 每镜重新弹出 | 每个镜头从空白开始重新弹出所有东西，上一镜的主体不留下、不变形 | 运动语言（动量不连续） |
| 没有物理 | 东西出现就是出现，没有受力起点、没有接触、没有重量和影子 | 物理 |
| 循环垫底 ≠ 声画叙事 | 只有口播 + 一条循环底乐，没有一个音效 | 节拍与声音 |
| 背景是静态图 | 点阵 + 光斑，和画面里发生的事没有关系 | 层次 |

**反直觉的一条：高级感常常来自删掉自由度，而不是加效果。** 好的指令会写大量限制：同一个形状连续变形、极少颜色、微量过冲、禁止全体相同动作。

## 一、导演 Brief（八项，写分镜之前必须写完）

写在 `tutorials/<id>.storyboard.md` / `explainers/<id>.storyboard.md` 最上面的“导演 Brief”一节，`scripts/qa/brief.mjs` 会检查八项是否都在。不确定的项先自己补全，写清理由。

| # | 项 | 回答的问题 | 本项目写法示例 |
|---|---|---|---|
| 1 | 目标 | 给谁看？看完记住哪一句？ | 抖音上用 AI 但还在复制粘贴的人；记住“agent 做完就交接，人只拍板” |
| 2 | 分镜与主次 | 每镜做什么？谁先被看见？ | 起势（hook，0–14 秒）→ 发展 → 收束；每镜写主体 / 次主体 / 背景 |
| 3 | 轨迹与相机 | 每个元素从哪到哪？相机为什么动？ | 任务卡沿抛物线从调研员飞到文案；相机只在任务卡出画时轻跟，末镜定住 |
| 4 | 运动与物理 | 谁受力？在哪里接触、回弹？ | 任务卡落到接收者头上：接触帧压扁 → 接收者下沉 4 帧后回弹 → 影子最后恢复 |
| 5 | 材质与光 | 什么手感？主光从哪来？ | 哑光纸片和黏土质感；主光全片固定在左上；每个落地物体有接触影 |
| 6 | 节拍与声音 | 音乐怎么分段？音效落在哪一帧？ | 口播卡点就是重拍；底乐按 4 个步骤换段；音效打在接触帧（见第七节） |
| 7 | 禁止项 | 哪些模板动作和效果不能出现？ | 见第九节，按本片再补 |
| 8 | 验收标准 | 怎样证明做完？怎样描述返修？ | 第十节的检查全过；返修写成“哪一帧、哪个元素、哪一项不对” |

把“高级一点”拆成能判断的具体要求。例：“高级一点” → “一屏最多 2 个强调色；主体动作前 4 帧有反向预备；所有落地都有接触影；没有任何发光描边”。

## 二、整片制作顺序

**口播 / 拍点 → 整片核心 → 分镜 → 主次与景深 → 力学 / 光 / 声 → 风格协调 → 导出检查**

- **口播就是拍点网格。** 原文是先定音乐 BPM（例 120 BPM、60 fps，一拍 30 帧）再做动画；本项目是口播带节奏的讲解，**`{a}` 卡点和字幕起点就是重拍**，底乐只管段落和情绪。不是每个拍点都要动——一句里只挑最重要的那个词做主事件。
- 每镜一个主任务，整片和每段都有“**起势 → 发展 → 收束**”。
- 导出后先看完整片，再逐帧定位不满意的地方（`scripts/qa/frames.mjs` 做逐帧查看页）。带着“哪一帧、哪个元素”的具体问题回到对应环节返修。

## 三、层次：主次、景深、错相

- **主体 / 次主体 / 背景**：每镜先写清观众先看谁、谁陪衬、谁垫底。主体有自己的轨迹和过程；次主体由事件触发、稍后回应；背景缓慢流动，托住氛围，但流动要和这一镜的事有关（比如任务卡飞过时背景的纸纹被带动一点）。
- **前中后景**：近景抢注意或补层次（只放少量、虚化或很大的东西），中景做事，远景托气氛。平面排版也可以只分上中下三层。
- **错相：同一件事，各层先后回应，不共用一条时间函数。** 30 fps 下的默认延迟（`src/fx/physics.ts` 的 `PHASE`）：

| 层 | 相对主事件 | 说明 |
|---|---|---|
| 主体 | 0 帧 | 先发起，先被看见 |
| 次主体 | +3–5 帧 | 被事件触发，幅度比主体小 |
| 相机 | +4–6 帧 | 跟主体，不领先主体 |
| 接触影 / 阴影 | +5–8 帧 | 随受力变化，最后恢复 |
| 文字标签 | +6–10 帧 | 动作站稳后再出，自己的进出时间 |
| 背景 | 持续 | 自己的慢周期，被冲击时只轻微回应 |

- **同一节奏、不同相位**：多个主体之间像“发起 → 回应 → 截断 → 接管”，不是各做各的。每个元素有自己的函数规律，合起来是一个总规律。
- **翻车信号**：所有层共用一个进度——PPT 同步感极强。**同一时刻只有一个主事件。**

## 四、运动语言：预备 → 拉伸 → 冲击 → 压扁 → 过冲 → 回稳 → 次级响应

以“一个东西从上往下落”为例（30 fps，帧数是起点，按材质调）：

| 阶段 | 做什么 | 默认量 |
|---|---|---|
| 预备 | 反方向先退一点，短暂停留，让观众预期落点 | 3–6 帧，反向 5–10% |
| 拉伸 | 沿速度方向拉长，强调加速 | 体积守恒：沿速度 ×1.1–1.25，垂直方向 ÷ 同值 |
| 冲击 | 第一次接触；**音效落在这一帧** | 接触帧 1 帧 |
| 压扁 | 受力后沿接触面展开 | 2–4 帧，×1.15–1.3 |
| 过冲 | 回弹越过稳态，保留动量 | 弹簧阻尼比 0.5–0.7；只在能量说得通的地方用 |
| 回稳 | 振幅逐渐减小 | ≤ 0.5 秒 |
| 次级响应 | 主体先趋稳，附属物、影子、周围元素的余波再收尾 | +3–8 帧 |

- **先有原因，再有形变**：压扁 / 拉伸来自速度和冲量（`squash(v)`），不是随便挑一个 easing。没有接触，就不准随机形变。
- **动量连续**：上一段的末速度 = 下一段的初速度。同一个主体切换状态时先接好速度和方向，再安排形变；**没有新的外力时，别在状态切换处把速度清零**。
- **一形贯穿多状态**：同一个形状连续变形成下一个状态（尺寸、圆角、颜色变，内容用短暂模糊换掉），比每段重新“弹出”一个新卡片高级得多。能留的主体就留着，变成下一镜的东西。
- **弹簧写成闭式解**：`springStep(t, t0)` 是弹簧的阶跃响应；一个值换了好几次目标，就是每次换目标叠加一个弹簧（`springTrack`），所以仍然只由 `t` 决定。前后两条边用不同刚度的弹簧（`twoEdge`），领先的一边先到、拖后的一边晚到，中间自然被拉长——tab 指示器、开关、进度条都用这个。
- 过冲要“微量”：弹簧阻尼比默认 0.62，`outBack` 的 s 不超过 1.3；Q 弹果冻感（多次大幅回弹）只给真正有弹性的东西。

## 五、物理：受力起点 → 接触与形变 → 后续运动与恢复

不写清物理，就会出现整幅推拉、死轮廓位移。常用的几种（都在 `src/fx/physics.ts`）：

| 效果 | 链条 | 函数 |
|---|---|---|
| 下落与弹跳 | 重力 → 接触 → 回弹（每次弹起变低） | `drop()`，返回位置、速度和每次接触的时刻 |
| 抛出与接住 | 起点速度 → 抛物线 → 落点接触 | `toss()` |
| 碰撞与惯性 | 接触 → 传力 → 被撞的继续运动 | `toss()` 的落点速度传给下一个 `springTrack` |
| 挤压与回弹 | 拉伸 → 压缩 → 恢复 | `squash(v)` + `impulse()` |
| 弯曲与扭转 | 施力 → 变形 → 向外传递 | `ripple(t, at, i)`：第 i 个元素晚 i 个延迟收到、幅度衰减 |
| 软体与水波 | 扰动 → 波纹 → 逐渐衰减 | `impulse()` 驱动缩放 / 圆环 |
| 粒子与流动 | 流场 → 轨迹 → 聚散 | `Particles`（只当背景，不当主体，不当“爆点”装饰） |

关键是**每个动作有明确的受力起点**，接触、形变和后续运动连贯发生。接收者被砸中要下沉，旁边的东西要被推开，影子要跟着变。

## 六、光与材质

- **一盏主光，全片方向统一**（本项目默认左上，`KEY_LIGHT`）。受光面、暗面、高光、接触影都从它推出来。
- 层次：主光定明暗与体积 → 弱补光保留暗部信息 → 轮廓光让边缘和背景分开（只在深色底上需要）→ 表面高光由形状、光源和粗糙度共同决定 → **接触影让物体落在地面上**（`ContactShadow`，离地越高越小越淡）。
- **关键物体别冻死**：位置不动时，高光、受光面、倒影也跟着轻微变化。
- **冲击传到环境时分层错相，别整幅一起抖**：被砸的东西最大，旁边的小一些、晚几帧，背景只轻微回应。`shake()` 不再套在整个画面外面。
- **禁止无理由发光**：没有光源的东西不发光；`boxShadow: 0 0 Npx 彩色`、霓虹描边、渐变彩色标签一律不用。要强调就用对比（明暗、大小、留白），不用辉光。

## 七、节拍、音效与音乐

- **BGM 管段落与情绪；SFX 打在“事件”上**：接触、落地、切换、确认、拒绝。音效从运动长出来：速度 → 呼啸（whoosh），冲量 → 撞击（impact），确认 → 轻响（tick / chime）。别等动画做完再随手贴。
- **微偏移比全卡同一帧自然**：预备的气声略早（−2～−4 帧）、撞击落在接触帧、碎屑和余响略后（+2～+6 帧）。全层卡在同一帧反而假。
- **给口播让路**：讲解视频的主角是人声。音效比人声低 12–18 dB，一秒最多 2–3 个，重要的词上宁可不放音效。
- 本项目做法：`scripts/generate-sfx.py` 合成一套免版权音效到 `public/audio/sfx/`；每个画面组件用静态属性 `sfx(cue, dur)` 列出事件 `{at: 帧, kind, gain}`，由 `TutorialVideo` 混进去。事件时刻**从同一个物理函数算出来**（例如 `toss()` 的落点时刻），不手写秒数。
- 声音要整句听：一段画面配一段声音，循环垫底 ≠ 声画叙事。

## 八、相机与镜头

- 相机要有理由：跟主体（主体要出画时轻跟）、揭示（拉开看全貌）、强调（推近看一个细节）。**末镜定住。**
- 相机延迟主体 4–6 帧，用临界阻尼弹簧跟（`follow`），不领先、不过冲。
- **不再默认每句字幕整幅推拉一次**（`beatTour` / `beatZoom` 是“整幅推拉”的来源）。画面变化靠主体自己的过程、次主体回应、相机跟随来做；丰富度检查照样要过。
- **本项目做法**：每个画面组件写静态属性 `camera(cue, dur)`，返回关键帧 `{at, x, y, z}`（看向舞台上的哪一点、推近多少）；`TutorialVideo` 用 `follow` 晚 5 帧、临界阻尼地跟过去。每个关键帧都要指向那一刻的主体。横向位移被限制在整版都在 x 24–1000 之内（不切字、不进按钮区），只有纵向和缩放会裁切，裁切边是软边。
- 浅底风格丰富度量不出来时，靠的就是这台相机 + 口播里每句话对应的真实事件（`ai-agent-team` 第二版：4.8 → 11.3）。
- 快速运动加运动模糊（`Smear`：沿速度方向拖 2–3 个渐淡的残影），速度一慢就没有。
- 转场要像材质会发生的事（纸会翻、会滑走），能用“主体带着镜头走到下一镜”就不用硬切加擦除。

## 九、禁止项（AI 味清单）

写进每部片的 Brief 第 7 项，再按本片补充。`scripts/qa/brief.mjs` 会在画面代码里查其中几项。

1. 全体同步淡入 / 弹出：一镜里多个元素用同一条时间函数、同一个方向同时出现。
2. 无理由发光：彩色 `boxShadow` 外发光、霓虹描边、文字辉光、光环。
3. 霓虹渐变：彩色渐变标签、渐变按钮、渐变描边。
4. 整幅推拉：没有理由的整屏平移 / 缩放（每句一次的 `beatTour`）；整屏一起抖。
5. 没有接触的随机形变：东西自己变大变小、转来转去，没有受力起点。
6. 居中大字 + 卡片堆 + 一屏写满字：画面里只放观众要看的那几个字，口播的话不要抄到画面上。
7. 一屏超过 2 个强调色（A/B 之外的强调色要么不用，要么是中性色）。
8. 爆点粒子、彩带、星星当“丰富度”。
9. Q 弹果冻：大幅多次回弹（`outBack` s > 1.3 只给真正有弹性的小东西）。
10. 每镜从空白重新弹出所有东西，上一镜的主体一个不留。
11. 动作做完再随手贴音效；音效盖过人声。
12. 图标线宽、圆角、端点不统一；一会儿等距一会儿平面。

## 十、参考：先看片，再拆关系，再写进 Brief

> 平时去哪看静态审美（留白、排版、层级、配色、首屏、微动效）、怎么看、做片时怎么用：见 [审美参考库.md](../审美参考库.md)。

- 一段真正好看的参考能省大量时间。做新风格前，先在参考画廊（https://guanmo-ai.github.io/awesome-ai-motion/ ，“知识讲解”“短动效”“产品宣传”分类，作品多数附公开提示词）选 1–2 个。
- **拆关系**：观察主次、运动、光和声，找出效果成立的原因，写成 Brief 里能执行的要求；不照抄画面，不搬原作素材。
- 本项目已经拆过的两个参考（2026-10-15）：
  - twoclipping《一个形状串起整套 UI》（14 秒，收藏 1.9 万）：暖灰底、黑白 + 至多一个强调色、一个字体；**一个形状从不切断**，按钮 → 加载 → 打勾 → 播放器 → 滑块……全是同一个元素在变尺寸、圆角和颜色，内容用短暂模糊换掉；光标的真实点击和拖动驱动每一次变化（因果）；弹簧到处都是、最多一点点过冲；禁止弹跳缓动、粒子爆点、发光、界面上的渐变、图标线宽不一、空镜。
  - stephanlivera《15 秒动态设计自由发挥》（收藏 1.2 万）：每段只用 1–2 个大色块（红、蓝、米白、黑、荧光黄）整屏铺满；巨大的字和单个大形状，留白很多；快速运动有明显的运动模糊；画面角落有细线刻度、时间码这类“编辑感”小字，但不抢主体；一次只发生一件事。
- 共同点（本项目以后默认照做）：**一屏一个大主体 + 大量留白；1–2 个颜色；一个字体家族用粗细做层级；运动有原因、有模糊、有余波；没有发光。**

## 十一、验收标准（在原有检查之外）

- [ ] 分镜文件有完整的“导演 Brief”八项，每镜写了主体 / 次主体 / 背景、受力起点 → 接触帧 → 恢复、错相、音效（`node scripts/qa/brief.mjs <id>` 通过）
- [ ] 画面代码里没有禁止项（同一脚本检查发光、渐变标签、`beatTour`、整屏 `shake`）
- [ ] 每个接触帧都有对应音效，且音效时刻由同一个物理函数算出；人声始终清楚
- [ ] 用 `scripts/qa/frames.mjs` 逐帧看过每个主事件前后 ±10 帧：预备、冲击、压扁、回稳、次级响应都看得出来，各层确实错开
- [ ] 一屏强调色 ≤ 2；接触影方向和主光一致
- [ ] 原有门槛：丰富度、卡点、扫片、手机宽度、格式、响度、大小
