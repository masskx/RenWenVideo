## awesome-opus5-5-videos（yihui-dev，MIT）：对标片的索引

703 条别人用 Opus 5.5 做的爆款片，每条有原帖链接、分类（`category`：motion graphics / explainer / 3d / game）、技术标签（`tech_tags`：canvas、svg、gsap、three、glsl、web audio、AI image）、作者公开的提示词原文（或注明只有原帖）。

**用法**：做片前按题材找 2–3 条同类（`category: explainer` 的讲解片优先），**看原片**（原帖链接 / Skillry 重制版），把它当对标作品写进 treatment 的“学什么 / 不拿什么”。不要只读提示词不看片：高质量来自片子本身，不是提示词的形容词。

## awesome-claude-5-5-videos（athemeroy，原创文字 CC BY 4.0，署名并附链接）：按制作路径分类

最有用的是 `docs/prompt-playbook.zh-CN.md` 的**七类制作路径**（每类都写了优势、要人核对的地方、可替换题目的模板）：

1. 零外部视觉素材的代码动画（Canvas 2D；一个角色造型 + 有限配色贯穿；先渲 5 秒样片查文字溢出、连续性、速度）
2. 教育讲解片：**内容比视觉更重要**（先列事实主张、来源、要用户确认的地方；“旁白发音未由模型试听”要明说）
3. 利用现有产品做宣传片（只用有权用的图标、截图、文案；不编功能和用户数据）
4. 三维场景：把“建场景”和“拍电影”分开（先灰模和镜头预览，再材质光照）
5. Opus 做导演、视频模型做像素（要写明视频模型的贡献，不能说成“纯代码”）
6. 基于现有影片的视觉改造与后期（先探测片长、画幅、帧率、音轨，列出必须保持不变的要素；逐时间段改造计划；10 秒样片）
7. 已有 skill / 引擎的短触发词（把预置系统和既有素材当真实输入披露）

还有一条必须守的披露原则：“一次提示”“纯代码”“零外部素材”“无人修改”是四件独立的事，不能拿一件说另一件。

**用法**：本仓库的三种素材情况（[导演方法.md](../导演方法.md) §素材）分别对应第 1、2 / 3、6 类；用生成图时按第 5 类的原则在发布包里写明。

## opus-video-prompts（joeseesun，没有许可证文件，README 声明提示词版权归原作者）：中文案例 + 写法经验

18 条带中文说明的提示词（一句话出片、中文讲解 + TTS、真人口播改线稿、Remotion 宣传片、高端极简产品片）。README 末尾的**写法经验**值得每次记住：

- **先分镜，后代码**；之后只改某一个镜头。
- **像导演一样给结构**：总时长、场景数、每场讲什么；**给参考视频比堆形容词有用**；多用 dramatic cuts、match cut、kinetic typography 这类镜头语言。
- **列禁用清单**：粒子爆炸、RGB 分离、镜头光晕、霓虹辉光、弹跳缓动——模板味大多来自这些。
- **确定性渲染**：每帧只由 t 决定。
- **让它自己看片、自己返工**：正式渲染前抽查关键帧，修掉重叠、拥挤、看不清。
- 成本：“一次成型”很多其实跑了两轮以上，预算按多轮迭代估。
