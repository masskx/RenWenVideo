# 音效：用 Openverse 找 Freesound 的真实录音

> 2026-10-16 加入。用户建议：需要音效时，去 Openverse（开放媒体搜索引擎，https://openverse.org ）找最合适的一条，直接下载用进视频；**音效以 Freesound 为主**（Openverse 收录的 Freesound 声音有几十万条）。不需要申请 key。

## 一、为什么要换

`scripts/generate-sfx.py` 合成的 10 种音效（whoosh、tap、thud、paper、tick、pop、chime、block、stamp）是正弦波和噪声拼出来的，几部片子下来听得出“电子味”，而且每个镜头只能在这 10 种里挑。导演层要求“音效落在接触帧上、和发生的动作对得上”——纸滑过桌面就该是纸的声音，机械臂到位就该是金属件的声音。真实录音更能做到这一点。合成音效保留，作兜底。

## 二、怎么用（`scripts/fetch-sfx.mjs`）

```bash
# 1. 找：用英文写“听起来像什么”，Freesound 的标题和标签基本是英文
node scripts/fetch-sfx.mjs search "paper slide on table" --n 10 --max 3

# 2. 取：选一条，起个本项目里的名字；可以裁起点和长度、调增益
node scripts/fetch-sfx.mjs get <openverse-id> paper-slide --from 0.05 --len 0.9 --gain -2
#    -> public/audio/sfx/fs-paper-slide.wav，来源记进 public/audio/sfx/CREDITS.json

# 3. 在场景里用：和合成音效一样
#    {at: p.land, kind: 'fs-paper-slide', gain: 0.2}

# 4. 发布前：生成署名（贴进 douyin/<id>/README.md 的“来源与说明”）
node scripts/fetch-sfx.mjs credits src/tutorial/scenes/<file>.tsx
```

- 下载的是 Freesound 的高质量预览（128 kbps 左右的 mp3，从 cdn.freesound.org 直接下载）；原始文件要登录 Freesound 才能下载，短音效用预览就够了。脚本会去掉开头的静音、按 `--len` 截短、加 40 ms 淡出、响度统一，存成 44.1 kHz 立体声 wav。
- 已经下载过的 `fs-*` 文件提交进仓库，下次直接复用；`CREDITS.json` 一起提交。
- Openverse 不带 key 的匿名请求有频率限制（会返回 429，脚本自动退避重试），一次检索最多翻到 240 条结果，写准关键词比翻页有用。

## 三、版权：只用 CC0 和 CC BY

- 脚本默认只检索、只允许下载 **CC0**（公共领域，不用署名）和 **CC BY**（可商用、可改编，但**必须署名**）。
- **不用**：CC BY-NC（不能商用——视频号带货、流量收益都算商用）、CC BY-ND（不能改编——裁剪、混音就算改编）、Sampling+ 等旧许可。
- 用了 CC BY 的音效，发布包 README 里必须写清：标题、作者、许可、链接（`credits` 命令直接生成）。CC0 不强制署名，但也照样列出来。

## 四、怎么挑（我听不见声音，就按这些挑）

1. **对得上动作**：查询词写物体 + 动作 + 材质，例如 `wooden block drop`、`metal latch click`、`servo motor short`、`keyboard single key press`、`camera shutter`、`cardboard box slide`、`ui click soft`、`whoosh short airy`。
2. **短**：接触音一般 0.1–0.8 秒，`--max 2` 过滤掉长的；长的用 `--len` 截。
3. **干净**：标题、标签里有 `foley`、`close`、`clean`、`single`，没有 `music`、`loop`、`ambience`、`voice`（除非要的就是环境声）；同一部片子的音效尽量出自同一位作者或同一套录音，质感统一。
4. **试听**：检索结果里每条都有 `listen` 链接；做片时把选中的几条和画面一起出一版草稿，**请用户听一下**，或者至少看波形：`ffmpeg -i public/audio/sfx/fs-x.wav -filter_complex showwavespic=s=800x200 wave.png`，起音要在开头（脚本已经去掉开头静音），不要有拖得很长的尾巴。
5. **音量**：仍按导演层——比人声低 12 dB 以上，`gain` 一般 0.12–0.3。

## 五、底乐也可以从 Openverse 找（可选）

Openverse 里也有音乐（`source=jamendo`、`ccmixter` 等），许可同样只用 CC0 / CC BY。目前底乐由 `scripts/generate-tutorial-music.py` 生成；想换成真实音乐时，同样记录署名。这一步还没有做成脚本。

## 六、配乐：`scripts/generate-score.py`（2026-10-26 起的默认）

用户 2026-10-26：“有配音，但缺背景音乐。”查下来两件事：

1. **以前的底乐其实听不见。** 渲染时音乐乘 `musicVolume`（0.07–0.08），说话时再压 `musicDuckDb`（18 dB）。旧底乐本身约 −19.5 LUFS，配音约 −19 LUFS，算下来停顿处音乐比人声低约 22 dB，说话时低约 40 dB——等于没有。
2. **MiniMax 的音乐接口对这个账号关了。** `music_generation` 返回 HTTP 410 / status 2153：“no longer available to new users”（2026-10-26 试过 music-1.5 / 2.0 / 2.5 / 2.6，api.minimax.cn 和 api.minimaxi.com 都一样；国际站 api.minimax.io 不认这个 key）。OPENAI 那个 key 和豆包语音 key 也没有音乐模型。用户选了“代码合成、做得更好”。

现在每支片用 `python scripts/generate-score.py <id> --preview`：

- **按片子的情绪选一种**（配置 `"score": {"mood": …}`）：`tension`（安全、事故：D 小调、低频脉冲）、`news`（科技新闻、发布：明亮的加九和弦、拨弦琶音、轻鼓）、`warm`（人、情绪、深夜：慢、软键盘、没有鼓、不用噪音 riser）、`wonder`（成品展示：利底亚上扬、闪的琶音）、`playful`（轻松、好笑：弹跳贝斯、拍手）。
- **跟着剪辑编曲**：第 0 帧就有第一个和弦（不淡入，钩子要有能量）；`"climax": <场景 id>`——速度在 ±8 % 里微调，让这个场景正好落在小节第一拍，前两小节收一点、配一个 riser，落下时整套进来并有一下低频冲击；`"lifts": [场景 id]`——后面转折的地方再小抬一次；每第 8 小节后半鼓停一下，长片不平；**最后一个字落下时一个和弦收住，≤ 1 秒后静音**（和 抖音技巧.md §三 的片尾规则一致）。
- **给人声让位**：1–4 kHz（人声最清楚的频段）挖约 7 dB，暗的情绪把和弦放低一个八度。
- **按这支片的配音定音量**：停顿处比人声低约 12 dB、说话时低约 22 dB，自动写 `musicVolume` / `musicDuckDb`（约 0.12–0.14 / 10）。
- `--preview` 出 `qa/<id>/score-preview.mp3`：配音按时间线摆好、音乐按渲染器完全一样的压低曲线混进去、整体 −15 LUFS——不用渲染视频就能听。
- 已有音乐的片子默认不换（只生成 `score.mp3`）；要换加 `--use`。旧的 `generate-tutorial-music.py` / `generate-pulse-bed.py` 留着，旧片还在用。

我听不见声音：每次生成后看一眼频谱（`ffmpeg -i score.mp3 -lavfi showspectrumpic=s=1200x400:scale=log:fscale=log spec.png`）和每 0.5 秒的音量——高潮前要有一个“收”、高潮要高 5–6 dB、人声频段要比上下两边暗——最后请用户听 preview。
