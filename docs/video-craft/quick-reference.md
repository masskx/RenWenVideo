# 速查（每次做片必读，只有这一页）

> 2026-10-18 起，这一页和根目录 `CLAUDE.md` 是仅有的必读规则。`docs/video-craft/` 里其他文档都是**可选参考**（提示词库例外：每期计划时按 §十 查一次），和这一页冲突时以这一页为准；旧的硬规则（导演层禁止项、物理动作链、八项 Brief、旧分镜模板）在 `archive/`。

## 〇、观众、题材、平台（全仓库只在这里定义，改这里就行）

- **观众**：说中文、正在用或想用 AI 工具的人——想知道最近出了什么、它能帮自己做什么。不限定职业或身份，不要把观众写窄（比如只写“研究生”“程序员”）。
- **题材**：AI 工具和 AI 新闻——编程 agent、新模型、工作流、创作者工具、研究工具。
- **平台**：同一条视频发 **微信视频号、抖音、小红书**；发布包里三个平台的标题、描述、话题分开写（小红书标题要带能被搜到的关键词）。

## 一、优先级（从上到下，前面的没做到，后面的不用做）

1. **钩子**：前 1–3 秒就给出、说出最有意思的东西。
2. **留人**：每隔几秒就有新东西（新数字、新画面、新对比）；不值这几秒的一律删。
3. **手机上看得清**：字大、用满全屏、要紧内容不放在平台界面会挡住的区域。
4. **忠于给定的脚本和素材**：不编事实；作者自述的说法标成“作者说”。
5. **打磨**（动效、转场、音效）——前四条都满足了再做。

## 二、脚本和素材怎么用

- 脚本一般来自策划 agent（growth）：钩子、正文、结尾、标题，格式随意。**以脚本为准**，按手里真有的素材决定场景数量、长短和画面——不套固定的场景数、镜头表或动画配方。
- 脚本有钩子就用；钩子弱或没有，从 [hooks.md](hooks.md) 里挑一个改写，并告诉用户用了哪一个。
- **不引流**（抖音不允许站外引流，用户 2026-10-21）：口播、画面、封面都不说“资料包 / 提示词包放在主页”“评论区扣××”“私信我”“加微信”，不放外链和二维码；脚本里有这类结尾就整句删掉，结尾落在内容本身，并告诉用户删了哪句。
- 钩子必须有片子里**真的出现**的画面撑着；第一人称只说真发生过的事（配音是用户本人的声音）。
- 脚本里的事实和数字要能在素材里找到出处；找不到的，问用户或删掉，不要补。创作者自己报的数字写成「据 @作者」。

## 三、时长和节奏

- 默认 **≤ 60 秒**；脚本确实需要更长、且用户同意时，在配置里写 `"maxSeconds"`。
- **0–3 秒是钩子**（全仓库统一按 0–3 秒）：第 0 帧就有内容，第一句口播 0.5 秒内开始。
- 每 2–3 秒有一个新变化；单个场景一般不超过 8–10 秒。
- 口播约 4.8–5.5 字/秒；短句（≤ 16 字）、口语、不用省略号。写法参考 [文案.md](文案.md) §七。

## 四、手机可读

- 要读的字 ≥ 40 px，字幕 ≥ 60 px（1080 宽画布）；纯装饰的小字不能带信息。
- 用满全屏；右侧按钮列和底部文案区不放要紧的字。具体版式数字见 [讲解动画规则.md](讲解动画规则.md)。
- 缩到 360 px 宽（`scan.mjs --phone`）还要读得清。

## 五、配音

- 只用用户本人的复刻音色（豆包语音），每个场景整段合成，逐字时间戳驱动字幕和卡点；edge-tts 只在用户同意时作备用。见 [配音.md](配音.md)。
- 每个场景写 `"pace"`（slow / calm / normal / brisk / fast），钩子一般 brisk。

## 六、画面风格

- 基准：`tutorials/deepseek-vs-opus55`——蓝图深底、细网格、等宽小字标注 + 黑体大字、A/B 两个固定强调色（琥珀 / 青）、一屏一个大主体、外部素材原样嵌入并署名。在它上面改进，不要丢掉这套样子。
- **不再有“AI 味”禁止项**：发光、粒子、整幅推拉、渐变都可以用，只要它帮钩子和留人、不挡字。是否用按素材决定。
- 外部素材：静音，右下角「@作者｜案例展示」，作者链接写进发布包 README。

## 七、必填简报（写进 `tutorials/<id>.storyboard.md` 的 `## 简报`）

钩子台词、钩子画面、核心看点（主要结论 / 数字）、结尾台词、三个平台的标题。另有 `## 参考提示词`（至少一条提示词库 id，见 §十）。其余（选题卡、镜头表、分镜细节）都可选，按素材需要写。模板：[分镜模板.md](分镜模板.md)。

## 八、提交前的检查

```bash
node scripts/qa/brief.mjs <id>            # 简报五项、参考提示词、时长和口播字数预算
node scripts/qa/cover.mjs <id>            # 封面
node scripts/qa/richness.mjs douyin/<id>/video.mp4
node scripts/qa/marks.mjs douyin/<id>/video.mp4
node scripts/qa/scan.mjs douyin/<id>/video.mp4 [--phone=s1,s2,s3]
npm run lint
```

另查格式（1080×1920、30 fps、H.264 + AAC）、响度（约 −15 LUFS）、大小（< 100 MB）。静帧自己先看，再给用户看：先看 `richness.mjs` 的拼图（`qa/<id>/richness.png`）和发布包的 stills 拼图，再看视频，按 §十 的“自查”过一遍。

## 九、可选参考

[README.md](README.md) 列出全部文档：配音、封面、音效、文案、动效、风格词典、概念画法、踩坑清单、发布与风格偏好、审美参考库。提示词库的用法见 §十（查库是必做步骤；库里的单条提示词照旧只是参考）。

## 十、做片手法（从提示词库学来的，每期都用）

**计划阶段必做**：定了钩子以后，按脚本类型跑 `node scripts/prompts/find.mjs --fit=<类型> --min=2`（类型：发布 对比 讲解 教程 盘点 新闻 开发者 轻松 中国风 音乐），再看 [选用指南.md](prompt-library/选用指南.md) §二 对应那一行和 [opus55-研读.md](prompt-library/opus55-研读.md) §五，挑 1–2 条，只拿一两招落到具体场景，按选用指南 §三 改成竖屏、豆包配音、真素材。用了什么写进分镜 `## 参考提示词`（id + 哪一招 → 哪个场景），`brief.mjs` 会查 id 是否真的在库里。给用户看的计划里也写一句用了哪招。

下面这些每期默认照做（出处：opus55-研读 §四、选用指南 §四）。素材做不到的，在 `## 参考提示词` 里写一句为什么。

**钩子**
- 第 0 帧就是完成的画面，不是空场慢慢亮起（`opus55/everestchris6-399895`、`lemo/DIRECTOR` §3）。
- 抽象说法换成人人能答的问题或一个摸得着的数字（`opus55/ldataengineer-823010`：“10% 坠机率的飞机你会上吗？”）。
- 要换钩子时，先写 3 个候选再挑（`opus55/archiveexplorer-560622`）；脚本给了好钩子就照用。

**留人**
- 一镜一个想法；一个构图停 1.4–3.5 秒，快段每 1.5–2 秒一个新想法（`opus55/everestchris6-399895`、`opus55/ik-builds-585923`）。景别和布局轮换，相邻两镜不用同一种布局。
- 转场由物件带出来：上一场的卡片、图标、数字变成下一场的主体，少用淡入淡出（`opus55/twoclipping-496100`、`opus55/daniel-haida-636937`）；素材允许时让一个主体（色块、圆点、线）贯穿全片。
- 每个动作有看得见的结果；讲功能先演出效果，再出名字（`opus55/koushikde-937635`）。
- 变速：至少一次明显加速或减速，高潮前留一口气（`lemo/DIRECTOR` §7）。
- 高潮放一个招牌镜头，要能不用特效名说清它是什么（`opus55/everestchris6-399895`；招式库：lemo 各风格 §8）。

**手机上看得清**
- 静音也能看懂：关键信息都上屏，不只在口播里（`opus55/howdevelop-733090`）。
- 上屏大字停留 ≈ 字数 ÷ 4.5 + 1.5 秒；关键时刻主体至少占画面高度 1/3（`lemo/DIRECTOR` §7、§8）。
- 截图不原样贴：拆成组件放大，只亮要看的那一块（`opus55/ho-ba-761062`、`lemo/living-screencast` 聚光定格）。

**忠于素材**
- 屏幕上每个数字、名字、说法都能在分镜 `## 素材和出处` 里找到（`opus55/everestchris6-399895` 的事实文件）；功能状态照实说：测试版不说正式版，计划中不说已上线（`opus55/howdevelop-733090`）。
- 讲别人用 AI 做的作品：“一次提示 / 纯代码 / 零素材 / 无人修改”是四件事，分开说；作者自述标「据 @作者」（`ac55/prompt-playbook.zh-CN`）。

**打磨和自查**
- 动效写成数字（时长、错峰帧数、弹簧参数），不写“要有弹性”（`opus55/flxrnc-251921`、`mg15/template`）。
- 渲染后先看拼图再看视频（`opus55/l3d1c-632524`）；单次画面静止尽量 ≤ 0.5 秒，每 30 秒总静止 ≤ 1 秒（`opus55/everestchris6-399895`；`richness.mjs` 只对 > 2 秒报警，更短的靠自己看）。
- 自查当作另一个人在审：按 §一 的优先级列问题，排 P0 / P1 / P2，先改 P0，改完再看一遍拼图（`opus55/voxyz-ai-345550`）。
- 声音对动作：每个看得见的落点都有声音（`lemo/DIRECTOR` §6，[音效.md](音效.md)）。

**不照搬**：别人的 CTA 和“评论领取”（§二 不引流）、虚构的产品和数据、16:9 / 方形构图、原提示词自带的 TTS 和合成配乐（§五）。
