# 速查（每次做片必读，只有这一页）

> 2026-10-23 起，必读的是这一页、[导演方法.md](导演方法.md)（怎么做好一支片）和根目录 `CLAUDE.md`；做每支片前再读一遍 [经验.md](经验.md)。`docs/video-craft/` 里其他文档都是**可选参考**，和这一页冲突时以这一页为准；旧的硬规则（导演层禁止项、物理动作链、八项 Brief、旧分镜模板）在 `archive/`。

## 〇、观众、题材、平台（全仓库只在这里定义，改这里就行）

- **观众**：说中文、正在用或想用 AI 工具的人——想知道最近出了什么、它能帮自己做什么。不限定职业或身份，不要把观众写窄（比如只写“研究生”“程序员”）。
- **题材**：AI 工具和 AI 新闻——编程 agent、新模型、工作流、创作者工具、研究工具。
- **平台**：同一条视频发 **微信视频号、抖音、小红书**；发布包里三个平台的标题、描述、话题分开写（小红书标题要带能被搜到的关键词）。

## 一、优先级（从上到下，前面的没做到，后面的不用做）

1. **钩子**：前 1–3 秒就给出、说出最有意思的东西。
2. **留人**：每隔几秒就有新东西（新数字、新画面、新对比）；不值这几秒的一律删。
3. **手机上看得清**：字大、用满全屏、要紧内容不放在平台界面会挡住的区域。
4. **忠于给定的脚本和素材**：不编事实；作者自述的说法标成“作者说”。
5. **打磨**（动效、转场、音效）——前四条都满足了再做。

## 二、想法、素材和脚本

- **输入是“想法 + 素材 + 出处”，脚本和分镜由我写**（用户 2026-10-23：“以后我只给你素材和想法，制作脚本你自己安排”）。策划 agent（growth）给的逐字口播、镜头表当参考：保留事实、合规要求和想强调的点，口播和画面我按 [导演方法.md](导演方法.md) 重新设计。
- 素材分三种情况（只有图片 / 图片 + 视频 / 没有素材），做法见 [导演方法.md](导演方法.md) §一；生成图只是缺素材时的辅助。
- 钩子由我定，从素材里最有意思的东西出发；需要时参考 [hooks.md](hooks.md)，并在计划里写明钩子是什么、为什么。
- **不引流**（抖音不允许站外引流，用户 2026-10-21）：口播、画面、封面都不说“资料包 / 提示词包放在主页”“评论区扣××”“私信我”“加微信”，不放外链和二维码；结尾落在内容本身。中文平台的其他隐性要求见 [平台与合规.md](平台与合规.md)。
- 钩子必须有片子里**真的出现**的画面撑着；第一人称只说真发生过的事（配音是用户本人的声音）。
- 事实和数字要能在素材里找到出处；找不到的，问用户或删掉，不要补。创作者自己报的数字写成「据 @作者」。

## 三、时长和节奏

- 默认 **≤ 60 秒**；脚本确实需要更长、且用户同意时，在配置里写 `"maxSeconds"`。
- **0–3 秒是钩子**（全仓库统一按 0–3 秒）：第 0 帧就有内容，第一句口播 0.5 秒内开始。
- **后台数据（[数据复盘-2026-10-26.md](数据复盘-2026-10-26.md)，做法见 [hooks.md](hooks.md)）**：观众平均只看 6–16 秒。第一句口播是“一个具体到荒唐 / 紧急的事 + 数字或时刻”，不报日期、不讲背景、不讲“这条视频本身”；**最大的结论或数字在前 10 秒说完**。知识快讯 35–50 秒表现最好；85–171 秒的长片平均也只被看 6–13 秒，只做值得收藏的教程（配置写 `"kind": "tutorial"`），并给一个能截图的清单画面。和观众有关的风险题，结尾给一个马上能做的动作（分享和涨粉的来源）。
- **选题（[数据复盘-2026-10-30.md](数据复盘-2026-10-30.md)）**：题材之间播放差 5 倍，比做工差得多。“反常的真事 + 和观众的工作 / 钱 / 前途有关”中位 8.6k；新模型跑分 1.7k；“这是 AI 写代码做的”1.9k（观众已不觉得新鲜，但收藏和涨粉最多）。开工前答 `inputs/_template/idea.md` 的选题四问；工具片从“替你省了什么”开场，不从“这是 AI 做的”开场。
- **抖音的开头、中段、结尾、发布**：[抖音技巧.md](抖音技巧.md)——开头画面 / 大字 / 声音三层同时到；15–20 秒放第二个钩子；结尾选五种之一，最后一句说完 1 秒内结束、最后一帧接回第 0 帧；不喊关注点赞（`brief.mjs` 判不过）。
- 每 2–3 秒有一个新变化；单个场景一般不超过 8–10 秒。
- 口播约 4.8–5.5 字/秒；短句（≤ 16 字）、口语、不用省略号。写法参考 [文案.md](文案.md) §七。

## 四、手机可读

- 要读的字 ≥ 40 px，字幕 ≥ 60 px（1080 宽画布）；纯装饰的小字不能带信息。
- 用满全屏；右侧按钮列和底部文案区不放要紧的字。具体版式数字见 [讲解动画规则.md](讲解动画规则.md)。
- 缩到 360 px 宽（`scan.mjs --phone`）还要读得清。

## 五、配音

- **默认用用户的 MiniMax 音色 `MashuaiDouyin01`**（用户 2026-10-24：“以后帮我做视频都用这个新的 MiniMax 音色”；`MINIMAX_API_KEY`；中文口播里夹英文名词它自己会读）。配置写 `"tts": {"provider": "minimax"}` 或不写 `tts`。每个场景整段合成，逐词时间戳驱动字幕和卡点。之前的豆包复刻音色保留（`"provider": "doubao"`），旧片和用户点名时用；edge-tts 只在用户同意时作备用。见 [配音.md](配音.md)。
- 每个场景写 `"pace"`（slow / calm / normal / brisk / fast），钩子一般 brisk。
- **每支片都有配乐**（用户 2026-10-26）：配置写 `"score": {"mood": tension / news / warm / wonder / playful, "climax": <场景 id>, "lifts": [场景 id]}`，`npm run tutorial:score -- <id> --preview` 出配乐和人声混音预览（`qa/<id>/score-preview.mp3`）；渲染时没有配乐或配音改过会自动重新生成。音量按配音自动定，不要手调回 0.07。见 [音效.md](音效.md) §六。

## 六、画面风格

- **2026-10-23 起不再套固定模板。** 用户：最近的片“像加了动画的 PPT，然后你照着念”“配色很屎、看着沉闷”。原因和证据见 [复盘-2026-10-23.md](复盘-2026-10-23.md)。cinema 主题（藏青黑底 + 金色，`src/tutorial/cinema.tsx`）降为可选的一种“世界”，不是默认。
- **每个镜头对照六条**（Xian 梵高做片法，[导演方法.md](导演方法.md) §三.〇）：一句一画（纯文字静止 ≤ 2 秒）；具体代替抽象（道具零件 `src/tutorial/props.tsx`）；底色就是情绪；视觉从题材长出来；一个画面一个主角（最多 1–2 个贴纸）；高潮多停 2 秒。
- **每支片按题材选风格和媒介**（[导演方法.md](导演方法.md) §三.4）：从 lemo 51 种 / mg15 15 种 / huashu 20 种视觉语言里挑，读完整份风格说明，再叠上**账号层**（[账号风格.md](账号风格.md)：字体、字幕、批注、取色方法、封面版式）。
- 每个场景要有**一个具体的东西在发生**（一个物件在变、一张图被拆开、一条曲线在长），不是“一块面板写一句话”；**上屏字不复述口播**，只放观众要“看”的东西（一个数字、一个名字、一句原话）。
- 满屏用：关键时刻主体至少占画面高度 1/3；不把内容缩在上半屏。
- **颜色从素材里找，不编**（huashu colour.md）：论文的图、产品界面、官网的颜色，`node scripts/qa/palette.mjs` 取色；底 / 面 / 中性字 / 一个强调色；亮、有对比、去色后层级还在；不用“深底 + 暖色强调 + 米白字”“米白 + 宋体 + 橙”这类 AI 通用样子；红只表示“危险 / 错误”。
- 和最近三支片比，结构、开场、招牌镜头、镜头路线、配乐形状、结尾六项至少四项不同（`node scripts/qa/compare.mjs <id>`）。
- 外部素材：静音，右下角「@作者｜案例展示」，作者链接写进发布包 README。

## 七、必填简报（写进 `tutorials/<id>.storyboard.md` 的 `## 简报`）

钩子台词、钩子画面、核心看点（主要结论 / 数字）、结尾台词、三个平台的标题；**加上 `## 导演` 的「模板」和「模板改造」**（2026-10-28 起每支片先从模板库选最合适的一个，再按内容改 3–5 处，别让片子都长一个样：[prompt-library/选用指南.md](prompt-library/选用指南.md) §〇、§〇.3，记一行到 [模板记录.md](模板记录.md)）**和十项**（点子、对标、结构候选、风格、底色、贯穿物件、招牌镜头、第0帧、高潮停留、和上一支不同），`brief.mjs` 缺一项就不过。`## 镜头表` 一句一行，强烈建议写。模板：[分镜模板.md](分镜模板.md)。

## 八、提交前的检查

```bash
node scripts/qa/brief.mjs <id>            # 简报五项 + 导演十项、时长和口播字数预算
node scripts/qa/echo.mjs <id>             # 上屏字复述口播超过三分之一就不过
node scripts/qa/cover.mjs <id>            # 封面
node scripts/qa/richness.mjs douyin/<id>/video.mp4
node scripts/qa/marks.mjs douyin/<id>/video.mp4
node scripts/qa/clutter.mjs douyin/<id>/video.mp4 [--frame channels]   # 主体大小、字幕上方空带、同屏颜色个数（只提醒）
node scripts/qa/scan.mjs douyin/<id>/video.mp4 [--phone=s1,s2,s3]
npm run lint
```

另查格式（1080×1920、30 fps、H.264 + AAC）、响度（约 −15 LUFS）、大小（< 100 MB）。静帧自己先看，再给用户看。

之后：`node scripts/qa/jury.mjs <id> --with=<对标>` 生成评审包，按 [评审表.md](评审表.md) 独立评审（或自评并注明），改完前三条再看。
