# 导演方法：一支片怎么从“想法 + 素材”做到能发

> 2026-10-23 起的做片方法。来源：8 个代码做视频仓库的导演 / 制作文档（[学习/](学习/README.md)）+ huashu-motion（[huashu-motion.md](huashu-motion.md)）+ Xian 的梵高做片法（[学习/xian-梵高做片法.md](学习/xian-梵高做片法.md)）+ 本仓库自己的复盘（[复盘-2026-10-23.md](复盘-2026-10-23.md)）。每条学到的东西落在哪里：[学习/README.md](学习/README.md) 末尾的表。
> 和 [quick-reference.md](quick-reference.md) 一起读：速查页管“必须守的”（钩子、手机可读、配音、事实、合规），这一页管“怎么做好”。
> 用户 2026-10-23：“以后我只给你素材和想法，制作脚本你自己安排。”“不要只用 Remotion，多参考别人优秀的代码。”“视频风格要和账号主题一致。”

## 〇、输入：想法 + 素材

用户（或策划 agent）给的是：**想法**（讲什么、为什么现在讲、想让观众记住什么）、**事实和出处**、**素材**（可能没有）。脚本、分镜、画面、节奏都由我定。

- 策划稿里如果附了逐字口播或镜头表，**当参考，不当定稿**：保留它的事实、合规要求和想强调的点，口播和镜头我重写（写法见 [文案.md](文案.md) §七；不复述、不念出处）。
- 事实只用素材和出处里有的；作者自述标「据 @作者」；没有出处的数字不上屏也不念。

## 一、素材的三种情况

先看手里有什么，再决定媒介和风格。三种情况都可以做好，做法不同：

| 情况 | 画面的主角 | 参考 | 要点 |
|---|---|---|---|
| **A. 只有图片**（截图、照片、图表、论文图） | 把图**贴纸化**、放进一个代码搭的世界里：粗白描边、投影、在大画布上排开，镜头在它们之间移动；图里的关键一行用“放大镜下一行亮起”、引线标注、数字抬出成卡片 | mg15 `19-paperclip`（回形针式）、`18-hanazi`（照片包装手法）；lemo `archive-lighttable`、`briefing-board`、`halftone-dossier` | 截图看不清就**重新排版原文**（标“原文”），不放读不了的小图；人物和账号打码；外部素材右下角「@作者｜案例展示」 |
| **B. 图片 + 视频**（录屏、案例片、实拍） | 视频当“证据”和“节奏”：录屏放进一个画出来的设备 / 窗口里，聚光定格、推近、快进加“N×”；案例片作为一个镜头而不是背景墙纸 | lemo `living-screencast`；ac55 第 6 类（基于现有影片改造）；mg15 `18-hanazi` | 先探测片长、帧率、可用的入出点；静音；一段素材只服务一个 read；别让视频满屏铺底、字压在上面 |
| **C. 没有素材** | 全部代码画：从题材里找一个能“变形”的具体物件当母题，选一种适合题材的风格（lemo / mg15），数据做成物件或图表 | lemo `swiss-motion`、`dataviz`、`data-physical`、`teardown`、`iso-infographic`、`whiteboard`、`one-line`、`pictogram-motion`；mg15 `08-morph`、`03-isometric`、`06-collage`；ac55 第 1 类 | 最容易做成“字卡 PPT”：每个场景先问“这里发生了什么事”，不是“这里放什么字” |

**生成图只是缺素材时的辅助**（用户 2026-10-23：“生成图片只应该是缺素材时的辅助，我更看重你用代码做动画的能力”）：需要一个具体场景（一间屋子、一个人物情境）而代码画不出质感时，才用 `npm run tutorial:images -- <id>`（`scripts/generate-tutorial-images.mjs`，`<Plate>`），一支片不超过一两张，发布包里写明“画面含 AI 生成图”。不能用生成图冒充真实截图、真实事件或真实人物。

## 二、账号层 + 单片风格层

同一个账号的片子要一眼认得出是同一个号，但每支片的“世界”可以按题材换（pdoom 的做法：每个图版风格不同，配色、字体、颗粒、语气统一）。**固定的东西写在 [账号风格.md](账号风格.md)**（字体、字幕、信号色、片头片尾、封面版式、语气）；**每支片自己选**：世界（深 / 浅底、材质）、媒介、镜头语法、母题、原生招式。

## 三、做片步骤

### 〇、让画面好看的六条（Xian 的梵高做片法，每个镜头都对照）

1. **一句话一个画面**：每句口播至少一个画面变化，纯文字静止不超过 2 秒。
2. **具体代替抽象**：用道具代替人和概念（两把椅子抖动 = 吵架；门自己开了 = 被一句话骗了），用数字代替形容词。道具零件在 `src/tutorial/props.tsx`。
3. **底色就是情绪**：钩子、低谷、高潮、结尾和讲事实的段落用不同的底，在转折处翻底（`<Ground a b k>`）。
4. **视觉从题材长出来**：材质、颜色、字体从这个题目里找（梵高 → 星月夜笔触、金画框、宋体；一篇论文 → 它自己图里的配色和图标），不套模板。
5. **一个画面一个主角**：周围最多 1–2 个贴纸或批注。
6. **高潮多停 2 秒**：让观众看清，也正好当封面。

### 1. 读材料，定一个点

- 一支片一个主体、一个目标、一个转折（lemo）。写一句 logline：“观众以为 ___，其实 ___，因为 ___”或“___ 想要 ___，但 ___，所以 ___”。
- 能贯穿的**母题**：题材里一个具体的、能变形的东西（一把钥匙、一张点阵、一条曲线、一个光标、一个回形针）。
- 不讲三条要点；要点多就选一条做透，其他的做成一个镜头里的“清单”或干脆不讲。
- 选题角度：冷知识 + 巨大反差（Xian）；开场不讲“X 是什么”，先讲一个具体、反常识的事实。

### 2. 对标

- 为**这个题目**挑 1–2 部参考：库里的样片（lemo poster + `demo/`、mg15 成片、`opus55` 的同类爆款，`node scripts/prompts/find.mjs`），或用户给的参考。
- 写下：**学什么**（构图、节奏、镜头语法、配色逻辑、声音结构）/ **不拿什么**（角色、设计、具体镜头、字体、品牌）。

### 3. 三个结构，选一个

至少写三个候选（一段旅程、前后对比、倒计时、一张清单翻过来、一个谜底、一次拆解、**情绪曲线**——钩子 → 困境 → 跌落 → 反问翻转 → 大反转 → 金句（Xian 梵高集）、**Hook → Why → Process → Essence → Tips**，每段 4–8 秒（meng shao 的知识区结构）……），每个几句话，选一个并写为什么。第一个想到的通常是套路。

### 4. 选风格和媒介

- **风格**：从 lemo 51 种 / mg15 15 种 / huashu 20 种视觉语言 / Xian 的 11 种风格里按题材挑一种（可以混两三种，Xian：“别只用一种风格”），**读完整份 STYLE.md 或提示词**，抄下它的材质、配色逻辑、两条缓动曲线、入场方式、镜头语法、声音调色板、原生招式和坑；再叠上账号层。
- **颜色是找来的，不是编的**（huashu-motion `references/colour.md`）：按顺序找——产品 / 品牌自己的值（官网 CSS、logo）、产品本身（界面截图的像素）、题材的世界（论文自己的图、实物照片），最后才自己编，并注明“自编”。`node scripts/qa/palette.mjs <素材图> 8 x:y …` 取色。配色按角色排：底（大部分）、面（约五分之一）、字（中性黑或白）、强调色（只有一个意思，几个百分点）、满屏色（可选，一两次，卡在节拍上）。**避开 AI 通用样子**：深底 + 一个暖色强调 + 米白字；米白底 + 宋体 / 巨大怪诞体 + 橙红；近黑 + 荧光绿；紫蓝渐变。我们的 cinema（藏青 + 金）就是第一种。去色看一张关键帧，层级还在才对。例：agent-compute-hijack 论文图 1 自己就是“蓝 = 直接要、被拒”“橙 = 资源劫持”两个世界，片子就用这两个世界，在“换个说法”时从蓝翻到橙（`src/lab/PropsLab.tsx`）。
- **2D 优先**（用户 2026-10-23：“像我这种只是分享知识的，还是优先在 2D 层面优化比较好”；之前叫停了 three.js 真 3D 版）：知识类片子默认 2D。画面“扁平”时用 2D 的办法解决——插画上的光影和投影、前中后三层和视差、2D 运镜（推、摇、在大画布上移动）、纸张 / 颗粒质感；不上 3D 引擎，除非用户要。
- **媒介**：
  - **Remotion**（`src/tutorial/`）：口播、逐字字幕、封面、卡点都已接好；适合以排版、图表、截图、录屏为主的片子。
  - **网页**（`pages/<id>/<scene>/index.html`，`node scripts/page-render.mjs pages/<id>/<scene>` 渲染）：Canvas 2D、SVG、WebGL 着色器、three.js、p5 / p5.brush、GSAP——需要大画布镜头、粒子、手绘笔触、3D、版画 / 网点 / CRT 等质感时用。`page-render.mjs` 认三种约定：mg15 / 我们的（`window.renderAt(t)` + `__ready`）、lemo（`window.render(t)` + `READY` + `DUR`）、huashu-motion（暂停的 GSAP 时间轴 `window.__timelines`）。**huashu 的 12 个模板**（动态排版、白板、拼贴、3Blue1Brown、财经图表、keynote、立体物件、UI 空间、小人讲故事、kurzgesagt、口播包装）一条命令起步：`node scripts/huashu-new.mjs --list`，`node scripts/huashu-new.mjs kinetic-type pages/<id>/<scene> --vertical`，改 `index.html` 里的 spec / 时间轴再渲。库里的样片源码可以直接拿来改（`docs/video-craft/prompt-library/code/`，注意许可）。渲出的片段再放进 Remotion 的场景里（`<OffthreadVideo>`），口播、字幕、封面照旧。
  - 一支片可以混用：大部分 Remotion，一两个招牌镜头用网页做。

### 5. 写 treatment（写进 `tutorials/<id>.storyboard.md`）

必填：简报五项 + **`## 导演` 十项**（点子、对标、结构候选、风格、底色、贯穿物件、招牌镜头、第0帧、高潮停留、和上一支不同；模板 [分镜模板.md](分镜模板.md)，`brief.mjs` 缺一项就不过）。再写：

1. **logline 和起承转合**；设定一句话（pdoom 的“插图论文”那种）；母题和它怎么变形。
2. **对标**：学什么 / 不拿什么。
3. **风格和媒介**：选了哪份 STYLE / 提示词，抄下来的几条关键技法；账号层怎么叠。
4. **镜头表**（`## 镜头表`，**一句口播一行**）：画面写**具体道具和它做了什么**，每个镜头写 **景别**（远 / 全 / 中 / 近 / 特写 / 插入）、**运镜**（推、拉、摇、移、跟、升降、甩、穿过）、时长、**为什么这样拍**、**reads**（观众按顺序要看懂的几件事，每件的起止时间）、**上屏字**（只写观众要“看”的：一个数字、一个名字、一句原话；不写复述口播的标题）。
5. **节奏表**：能量曲线（钩子、密集段、一次停顿、高光、收尾），每一秒发生什么。
6. **声音表**：每段的环境、拟音、音乐状态；哪里安静；哪两处用声音做转场。
7. **原生招式**：这一支片只有这个媒介能做的一个镜头，放在哪里。

自查：每个镜头有事件吗？每个 read 有时间落地吗？有没有任何一个画面是“一块面板写一句话”？主体在关键时刻占画面高度 1/3 以上吗？和最近三支片相比，结构、开场、招牌镜头、镜头路线、配乐形状、结尾六项至少四项不同吗？

### 6. 先证明画面

用**真代码**做 3 张风格帧（其中一张是招牌镜头）+ 钩子第 0 帧，渲成静帧，和对标的 poster / 截图并排看（`scripts/qa/compare.mjs`，见 §四）。每张都要能当海报。不行就回到第 4 步，不要带着不行的画面去做全片。

### 7. 配音、制作

- 口播先定稿、配音（用户的复刻音色），逐字时间戳驱动卡点和字幕。
- 一个场景一个场景做，先摆关键姿势（静帧能看懂），再补中间的动作。

### 8. 审片（交给用户之前）

1. 机器检查：`brief.mjs`、**`echo.mjs`**（上屏字复述口播超过三分之一就不过）、`richness.mjs`、`clutter.mjs`、`marks.mjs`、`scan.mjs --phone`、`cover.mjs`、`npm run lint`。这些只说明“有没有毛病”，不说明“好不好”。
2. **三档放大**（cab）：全片拼图（每 1–2 秒一帧）看结构；关键动作逐帧条（0.1–0.2 秒一帧）看动作；脸、手、字、接触点局部放大看工艺。读拼图时问：这一帧观众在看哪里？看懂了吗？
3. **和对标、和最近三支片并排**（`scripts/qa/compare.mjs <id> --with=<ref>`）：像不像对标的质量？像不像我们自己的上一支片（像就是失败）？
4. **独立评审**：`node scripts/qa/jury.mjs <id> --with=<对标>` 生成评审包（每 0.5 秒一帧的总览、并排图、关键帧、手机帧、导演决定、口播、提示词），按 [评审表.md](评审表.md)（mg15 评委提示词按抖音知识区改写：钩子、点子、画面、字、动效、设计、手机、声音、事实、平台十项）由另一个 agent 来评（用户允许时开子代理；不允许时我自己按它的格式严格评一遍，并在报告里注明“自评，非独立”）。按影响排序的修改至少改完前三条，再评一轮。
5. 写诚实的自评：最强的、最弱的、多给时间会改什么。

### 9. 交付和复盘

- 发布包照旧（`douyin/<id>/`）。
- 在 [经验.md](经验.md) 写一条：这支片试了什么、评审分、用户的原话和打分、下次要改的一件事。
- 请用户给一个 1–10 的分和一句话；有分才能知道方法有没有在变好。
