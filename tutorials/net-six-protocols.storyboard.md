## 简报

- 钩子台词：你对手机说“开灯”，灯亮之前，这句话至少要过6种协议。（hooks.md §一 第 1 种：荒唐的事实 + 数字——三个字、6 种协议）
- 钩子画面：第 0 帧——浅灰绿底上一块等距小岛：左下一部手机（屏幕上一个黄色气泡「开灯」）、右上一盏没亮的台灯，中间一条虚线路线绕过路由器和两台服务器；上方巨大的「6」+「种协议」，下面一排 6 个小方块图例（IP、TCP、UDP、DNS、HTTP、MQTT，各是自己的颜色）。说到“6种协议”时 6 个图例方块依次弹起。
- 核心看点：一句话从手机到灯要走的一条路：DNS 问路（走 UDP，不握手、丢了再问）→ IP 给每个包贴地址、路由器一跳一跳传（TTL 64 → 63 → 62）→ IP 不管丢没丢，所以 TCP 先三次握手、编号、丢哪个补哪个 → HTTP 写真正的请求，服务器回 200 → MQTT 把命令推给一直在线、订阅着自己频道的灯；回头看是一层套一层：HTTP 装进 TCP，TCP 装进 IP。“6 种协议”第 1 句就说。
- 收藏点：结尾前的“剖开的包”（招牌镜头，约第 48–52 秒）就是一张能截图的分层图：IP ⊃ TCP ⊃ HTTP + 旁边 UDP / DNS、MQTT 各在哪一层，停 ≥ 2 秒。
- 结尾台词：下次灯没亮，你就知道该问是哪一层了。（抖音技巧.md §三 第 2 种：回扣开头——回到那盏灯；最后一帧回到第 0 帧的小岛构图，灯亮着，能接回开头）
- 标题·视频号：你说一句“开灯”，灯亮之前要过 6 种协议
- 标题·抖音：一句“开灯”，背后要过6种网络协议
- 标题·小红书：一条视频讲清 6 种网络协议｜IP TCP UDP DNS HTTP MQTT 是怎么配合的

## 导演

- 模板：lemo/iso-infographic（等距信息图）。为什么是它：选用指南 §〇 把“原理 / 概念讲解”给到 whiteboard，备选里有 iso-infographic；网络协议讲的正是一个**系统**里一样东西怎么走——模板 §8 原生招式自己就写着“one packet in a network”（focus + context）、“a letter through the post”（tracked subject）、“a software stack”（strata cross-section）。whiteboard 10-29 刚用过。照搬了：§1 真等距（30° 轴、不透视、实体不描边、每个面三种色调）、信息图家具长在世界里（引线标签针、虚线剖切线、斜线剖面、追踪环、图例、路线）；§2 小岛浮在浅色底上、底下一层淡点阵、边缘露出剖面；§3 浅中性底 + 5–7 个平色、**一个颜色只代表一个意思**（像图例）、主角色保留（focus + context：别的变灰，只有那个包有颜色）；§4 标签针（圆点 → 竖引线 → 横线 → 字）、字带一圈底色光晕、**字幕是地图标签**（浅色小圆角卡、墨色边框先画、里面一个小等距方块当图例、字擦进来）、片尾可以是图例；§5 线先走、东西后到（路线先画出来包才跑）、剖开 = 剖切线 → 外皮沿法线滑开 → 斜线剖面、实体只靠运动入场不靠透明度、落地压扁 ~18 %、包沿折线走 ease-in-out；§6 跟着路线走、拉远看全貌、一个画面里放一个圆形放大框；§8 原生招式：Tracked subject（那句“开灯”）、Focus + context、Cutaway、Strata cross-section（招牌）。引擎直接移植它 MIT 的 `engine.js`（Canvas 2D，`Iso` / `tri` / `pin` / `ring` / `cutLine` / `hatch` / `inset`），每帧只由时间决定。不照搬：它的咖啡样片故事、小岛、人物、配乐。
- 模板改造：配色：示例的奶油 / 红 / 绿 → Wireshark 默认着色规则里每个协议本来的颜色（TCP #E7E6FF、UDP #DAEEFF、HTTP #E4FFC7、Routing #FFF3D6 给 IP 和路由器、TCP SYN/FIN #A0A0A0 给握手、TCP RST #A40000 只给“丢包”、字 #12272E、底 #ECF0EB），浅色当顶面、同色相加深当两个侧面（网络工程师抓包时就是看这几种颜色认协议，画面和题材是一个世界）；贯穿物件：模板的“追踪对象”是一个物件 → 那句「开灯」本身：一个黄色（Wireshark 高亮黄 #FFFC9C）气泡，被装进一层层盒子、最后变成灯光；字幕：地图标签卡里的图例小方块 → 跟着当前那一站的协议换颜色（字幕本身就是图例）；字：Jost → Inter Display（数字、英文）+ 思源黑体（中文）+ JetBrains Mono（协议名、地址、200 OK 这类“抓包里的字”）；声音：卡林巴 / 马林巴 → 我们合成的 playful 配乐 + 每个协议一种拟音（UDP 抛出的 whoosh、TCP 握手三下 tick、HTTP 纸张、MQTT 一声 ping、灯亮一声开关）
- 点子：观众以为 IP、TCP、UDP、DNS、HTTP、MQTT 是六个要背的名词，其实是一句话从手机走到灯的一条路上的六站，而且一层套一层。
- 对标：iso-infographic 样片（`code/lemomo-ai__lemo-opuscar/3961ddb/styles/iso-infographic/demo`，学：小岛 + 剖面边、标签针的生长顺序、追踪环、线先走物后到、三色调面、拉远收成一张信息图；不拿：咖啡供应链故事、小岛上的建筑和人物、配乐）；我们的 llm-same-prompt-diff-output（10-29，原理片，学：一个能看见的机制 + 第二钩子划掉常见理解；不拿：白板、笔、谜底结构）。
- 结构候选：① 一条路（旅程）：手机 → DNS → IP 路由 → TCP 握手 → HTTP 请求 → MQTT 推到灯 → 灯亮 → 剖开那个包看分层；② 六层楼（模板 §11 “one building, floor by floor”）：一座剖开的楼从顶层 HTTP 往下摇到 IP，每层一个协议；③ 对比：TCP vs UDP 两块小岛并排（快递签收 vs 扔纸飞机），其他协议放边上。选 ①：观众平均只看 6–16 秒，“开灯”这件事比一栋“协议楼”具体得多，每一站都有一个新画面（每 5–7 秒换一站），而 ② 的“分层”留到结尾当招牌（剖开的包），③ 的 TCP / UDP 对比在路上自然出现（问路用 UDP、送话用 TCP）。
- 风格：lemo/iso-infographic 的系统 + Wireshark 的协议颜色。底 #ECF0EB + 淡点阵；小岛顶面 #FAFBF8、剖面土层用 Routing 米黄；手机 / 灯 / 服务器是三色调实体；每个协议一个颜色（见模板改造）；墨 #12272E 只给引线、标签、路线；红 #A40000 只出现在丢包那一下。三条关键技法：线先走（路线、引线、剖切线先画，包后到）；focus + context（讲哪一站，别的都褪成暖灰，只有那一站和那个包有颜色）；三色调面（顶亮、左中、右暗，暗面偏冷）。
- 底色：全片同一张浅灰绿底（模板就是一块浮在浅底上的小岛）；情绪靠 focus + context 的“褪色 / 回彩”：讲到哪一站，其他褪灰；TCP 丢包那一下全岛压暗只剩红色那一格（低谷）；灯亮那一下全岛回彩、灯光黄铺开（高潮）；结尾剖开的包在浅底上单独放大。
- 贯穿物件：那句「开灯」——第 0 帧是手机屏幕上的黄色气泡；DNS 那站它在手机里等着；IP 那站它被装进一个贴着地址条的米黄盒子（IP）；TCP 那站盒子被切成编号的 1 2 3 4；HTTP 那站它被写成一封绿色的信「POST /light {"on": true}」；MQTT 那站它变成一个小紫包顺着长连接滑到灯里；灯亮时气泡的黄变成灯光；结尾那个包被剖开，最里面还是那个黄色「开灯」。
- 招牌镜头：第 47–52 秒：镜头推近停在路由器上空的那个包，剖切线沿包的一角画过去 → IP 外皮（米黄、贴地址条）沿法线滑开 → 里面露出 TCP 的淡紫层（印着序号）→ 再滑开露出 HTTP 的绿信 → 最里面是黄色「开灯」；每一层边缘留斜线剖面，三根标签针依次长出（IP · 地址、TCP · 编号和补发、HTTP · 真正的话），旁边一列图例补上 UDP / DNS、MQTT 各在哪；这是模板 Strata cross-section + Cutaway 合在一个包上。配乐高潮落在灯亮那一拍（mqtt 场），这一镜是高潮后的“看清楚”。
- 第0帧：浅灰绿底 + 淡点阵；等距小岛（剖面边）上：左下手机（黄气泡「开灯」）、右上灯（没亮）、中间路由器、DNS 服务器、云服务器，一条墨色虚线路线连起来；上方巨大的「6」+「种协议」；下面 6 个协议色小方块图例带名字；角落小字「示意」。
- 高潮停留：灯亮那一下（约第 41–44 秒）：灯光的黄色圆锥铺开、全岛回彩、追踪环套住灯，停 ≥ 1.5 秒；之后剖开的包再停 ≥ 2 秒；最后一句说完 0.5 秒内结束。
- 配乐：playful（轻、拨弦感，配一站一站往前走），climax = mqtt（climaxAt 落在灯亮那一拍），lifts = tcp（第二钩子“但 IP 只管送”）；安静两次：tcp 场开头 0.3 秒（丢包之前）、mqtt 场灯亮前 0.3 秒。
- 和上一支不同：最近三支 huashu-motion-1d95（swiss-motion）、mistral-large4-open-weights（telestrator）、llm-same-prompt-diff-output（whiteboard）。结构（一条路的旅程，不是账单 / 一个时刻三个机位 / 谜底）、开场（等距小岛 + 巨大的 6，不是 1.95 / 官方柱图 / 白板上的字）、招牌镜头（一个包被一层层剖开，不是小数点飞走 / 画斜纹 / 笔分叉）、镜头路线（沿路线跟拍 + 推近 + 拉远看全岛，不是版式擦出 / 定格 / 白板横移）、配乐形状（一站一个拟音、高潮在灯亮）、结尾（回到灯亮的小岛）——六项都不同。

## 素材和出处

- 全部代码画，没有外部画面。事实见 `inputs/net-six-protocols/idea.md`：DNS（RFC 1034 / 1035，UDP 53，解析器重发）、UDP（RFC 768）、IP（RFC 791，逐跳 TTL 减 1）、默认 TTL 64（Linux ip-sysctl）、TCP（RFC 9293，三次握手、序号、重传）、HTTP（RFC 9110，200 OK）、MQTT（OASIS MQTT 5.0：发布 / 订阅、Broker、跑在 TCP 上、固定包头最小 2 字节）。
- 画面里的地址是文档保留地址：203.0.113.8（RFC 5737）、api.example.com（RFC 2606）。智能家居链路是常见做法的示意，上屏标「示意」。
- 颜色：Wireshark 默认着色规则（release-4.4 `colorfilters`）。
- 引擎：lemo-opuscar `styles/iso-infographic/demo/engine.js`（MIT，LemoLab），移植进 `src/tutorial/iso.ts`。
