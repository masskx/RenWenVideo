# 会动，不等于看懂 · 分镜

- 来源：数字生命卡兹克（X @Khazix0918）2026-10-15 的 X 长文《分享一个最近很惊艳的开源 Skill，一句话让 AI 搓出任何原理的科普视频》（https://x.com/Khazix0918/status/2110587546271191166 ）。讲 Anatomy Skill（github.com/wheresryan22/anatomy，理念 “The object is the explanation”）：一句话做出可交互的机械模型动画；作者发现门外汉看不懂纯动画，于是让 AI 在动画基础上直接生成有讲解、有配音的科普视频；附带耗时、额度、准确性提醒，以及 Karpathy 关于“怎么理解 AI 生成内容”的几种形式。原文配图、视频截图都不出现；机芯是我们自己按原理画的示意图。

## 选题卡

- 一句话：会动，不等于看懂——AI 已经能把任何原理做成一台会转的模型，但让门外汉看懂的，是旁边那条按顺序讲的讲解。
- 视角：讲述者（第一人称“我”，用户本人的声音）；卡兹克的经历当开场故事讲成第三方。“我”只说真事：这个频道的视频确实是和 AI 一起做的，“说到哪个零件就只让哪个零件动”是我们做片的规矩（导演层“同一时刻一个主事件”、分镜模板“只画口播说了的东西”）。
- 主角：先是卡兹克（试用 Anatomy、看懵、加讲解）；后半段换成观众自己的好奇心。
- 冲突：画面精致到齿轮咬合，门外汉仍然说不出它怎么计时——“物体本身就是解释”对不懂的人不成立。
- 我们的观点：① 原文说“加讲解”；我们说清楚加什么——四个问题（这是啥、在发生啥、为什么、有啥用），并且当场用这块表演示一遍，让观众自己感受“有讲解”的差别；② 我们自己做片的体会：画得精细不难，难的是讲的顺序——说到哪个零件，画面上就只让那个零件动（当场对比“全都在动”和“只动一个”）。
- 观众带走：下次对一个小问题好奇，让 AI 专门做一节课，提问时带上那四句；关键参数自己核对。
- 原文用多少：Anatomy 理念和机械表例子、作者看懵的经历、“加讲解和配音、一轮直出”、耗时（一个半小时）和“自己学用便宜配置也够”、准确性提醒、“以前的学习材料是做好了发给所有人”。删掉：安装提示词、显卡 / TCP / 刹车案例、额度百分比、Transformer 被封的插曲、Karpathy 的 ASD-STE100 和图表 / 网页 / 视频四种形式（只留结论的意思）、模型名字。

## 导演 Brief

1. 目标：给对 AI 做科普 / 学习工具感兴趣、或者自己也在用 AI 做内容的人看。看完记住一句：**会动不等于看懂；让 AI 讲东西，要它回答四个问题，并且一次只让一个东西动。**
2. 分镜与主次：起势 = hook（机芯转动 → 问“它怎么计时”）、story（一行指令 → 机芯拆开再装回）；发展 = conflict（三个问号挂在零件上）、turn（问号换成四行讲解）、demo（按顺序讲一遍：发条 → 齿轮 → 擒纵 → 摆轮 → 一秒八拍）；收束 = view（全都在动 vs 只动一个）、caveat（计时盘 + 卡尺核对）、ending（一排做好的“课程盒”滑过 → 为你一个人组装的一节课 → 四句提问）。**贯穿全片的主体是同一台机芯**：发条盒、三级齿轮、擒纵轮、擒纵叉、摆轮；次主体：问号吊牌、讲解标签、卡尺、计时盘；背景：蓝图网格。
3. 轨迹与相机：齿轮按齿数比真实联动（擒纵轮每拍跳一格，整个轮系跟着同步跳，不是匀速转）；摆轮按正弦来回摆，摆过中点那一刻擒纵叉翻转、擒纵轮放行一格——这一刻是接触帧。相机只推向正在讲的零件（≤ 1.3 倍；HUD 标题下垫一条不透明页眉带，画面可以滑到标题下面而不叠字；超过 1.1 倍时画面水平居中，标签只放在舞台 x 60–820），慢句上相机停住。
4. 运动与物理：齿轮“跳一格”用弹簧（快到位、微过冲、回稳）；拆解时零件沿径向抬起分开（预备下沉 → 抬起 → 停在空中微晃），装回时依次落位压缩回弹（接触音 part-seat）；问号吊牌从上方落下，挂绳带阻尼摆动；卡尺的钳口合拢在齿轮上（接触 → 读数跳出）；“全都在动”段落各零件不同步乱转，“只动一个”时其余零件刹停（减速到 0 有微小回弹）。
5. 材质与光：蓝图深底 + 细网格，零件是平涂面 + 浅钢色线；被讲到的零件填琥珀，其余压暗；不发光、不用渐变；只有摆轮上的红宝石轴承是一个小琥珀点（有来源：真实机芯的宝石）。
6. 节拍与声音：口播卡点是重拍；底乐很轻。音效用 Freesound 真实录音：擒纵 `fs-watch-tick`（×1/2 慢放时每 2 拍一声，×1/4 时逐拍，实速时每 2 拍一声且更轻，避免满耳哒哒）、零件落位 `fs-part-seat`、拧发条 `fs-wind-click`、讲解卡 `fs-paper-slide`；合成的 tap / whoosh-short 兜底。全部低于人声 12 dB 以上。
7. 禁止项：导演层第九节全部；本片补充——不出现卡兹克或任何真人形象、不放原文截图和他做的视频画面；不写原文没有的数字（额度百分比不讲，“一秒八拍”是机芯常识并说“常见的”）；不点模型名；一屏强调色 ≤ 2。
8. 验收标准：导演层第十一节全部 + 原有门槛；补充——齿轮相邻两只的转速比等于齿数反比（逐帧看不打滑）；擒纵放行发生在摆轮过中点那一帧；demo 每句话只有被讲的那个零件在动或高亮；所有要紧内容在 y 330–1590。

## 静帧判断

- 第一轮静帧：机芯咬合成立（放大检查，相邻齿轮齿对齿缝），擒纵轮做成环形才看得见下面的小齿轴和四轮咬合；擒纵叉的两块叉瓦对准擒纵轮。问题：conflict 的两条量表压在“问题 3”的标题上 → 量表在第一个问号落下前淡出；问号吊绳从画面顶上一直拉下来穿过标题 → 绳子只画 90 px；计时盘刻度字被扇形盖住 → 刻度字移到表圈外。
- 丰富度：第一稿只有 6.6，15 格几乎不变。原因：**旋转的齿轮在检查用的 108 px 灰度图里几乎不算变化**（齿轮转了还是同一个轮廓），慢放下更明显。改法都要有理由：默认速度改成 ×1/2（只在讲擒纵时 ×1/4）；字幕换句时标题跟着换；“看懵了”时整台机芯起雾变暗；讲解卡每填一行，机芯上的高亮跳到这一行说的零件；“全都在动”段落所有零件发亮并晃动，“只让它动”时其余刹停变暗、擒纵轮放大；hook 里“AI 一句话就能做出来”时机芯拆开再落位；结尾课程盒改成实心、每个盒子名字不同（传送带周期不能刚好等于 2.5 秒的位移）。到 9.3 后，最大的一步是相机：原来沿用 agent 片“≤ 1.1 倍、不许往下看”的限位，相机几乎动不了；改成 HUD 标题下垫页眉带后，相机能推到正在讲的零件（≤ 1.3 倍），最后 10.2、没有不变格。
- 推近后讲解卡顶部滑进页眉带 → turn 镜头相机只往上看（y 400）；结尾的“为你做的一节课”框顶被页眉压住 → 机芯缩到 0.55 并下移。
