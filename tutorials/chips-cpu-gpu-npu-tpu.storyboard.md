## 简报

- 钩子台词：同一个80亿参数的模型，CPU每秒约吐6个字，GPU能到200个。（hooks.md §一 第 6 种：结果先行的对比；数字是只看内存带宽的理论上限，上屏标「估算」）
- 钩子画面：第 0 帧——3D 斜俯视：上面一颗 CPU 封装（8 个大核）冒出零星几个白色小方块（字），下面一颗 H100 级 GPU 封装（中间大芯片 + 两边 6 个 HBM）喷出一大团金色小方块；左侧大字「≈6 字/秒」「≈200 字/秒」，顶部小字「同一个 80 亿参数模型 · 估算的理论上限」。
- 核心看点：CPU 是几个大核、GPU 是上万个小核（H100：132 × 128 = 16,896）、NPU 是手机和电脑里只做乘加的省电专区（Copilot+ PC 要求 ≥ 40 TOPS）、TPU 是 128 × 128 乘加器排成的脉动阵列；大模型几乎全是矩阵乘法，但真正卡它的是搬数据——每出一个字要把 16 GB 权重读一遍，电脑内存 128 根线 ≈ 96 GB/s，H100 的 HBM 5,120 根线 3,350 GB/s，差 35 倍；线太多只能把内存叠起来贴着 GPU 放，同容量约吃 3 倍晶圆（美光），AI 把内存抢光，显存现货价涨了约 3 倍（据 TrendForce）。
- 收藏点：结尾前一帧是四颗芯片 + 内存总线的一张“对照总图”（核心数 / 擅长 / 数据通道），停 1.5 秒，可截图。
- 结尾台词：所以大模型缺的不只是算力，是搬数据的路。（抖音技巧.md §三 第 3 种：一句翻转的判断；镜头快速拉远回到第 0 帧的两颗芯片）
- 标题·视频号：CPU、GPU、NPU、TPU 到底差在哪？大模型为什么非要 GPU，又为什么越来越贵
- 标题·抖音：同一个模型，CPU每秒6个字，GPU 200个
- 标题·小红书：CPU / GPU / NPU / TPU 区别｜3D 拆给你看：大模型为什么要 GPU、显卡为什么涨价

## 导演

- 模板：lemo/teardown（拆解）。为什么是它：选用指南 §〇 把“产品 / 硬件 / 系统架构拆开看”给到 teardown；用户要“三维的细致分析和讲解”，teardown 是库里唯一以真实 3D 渲染为引擎的拆解模板（three.js PBR）。照搬了：§2 物理材质（硅片清漆、铜、金、基板）、棚拍光（暖主光、跟着机位走的冷轮廓光、顶光、环境反射）、深石墨底只留柔和接触阴影；§4 标签结构（强调色两位编号 + 名称 + 一行等宽规格，引线落在零件上，从 3D 点逐帧投影）、透视里的尺寸线；§5 分层分离（上层先走、错开 0.15–0.2 秒、长停稳）、成排零件按波浪抬起；§6 镜头语法（拆开时环绕、微距推近、穿过层间、快速拉远收尾），转场就是镜头穿过物体；§7 干净的木琴 / 马林巴式配乐 + 每次分离和落位都有声音。不照搬：键盘、PCB 实物数据（我们没有 CAD）、样片结构。
- 模板改造：实物 CAD → **按公开数字建的示意模型**，每一镜标「示意」，只上能找到出处的数字（会改性格：从“这台机器的精确档案”变成“一类芯片的结构图”，失去的是“精确到毫米”）；强调色 #ff6b3d → **SK 海力士官方展台 HBM 堆叠的金 #E0B84D**（PR #63 素材里取），只给“量出来的东西”和“内存”这条线（尺寸线、编号、HBM、带宽、晶圆）；一个产品 → **四颗芯片 + 一条内存总线**，结构用 teardown §11 的“沿信号走一遍”；原生招式“层间探入”换成**波浪抬起**的两种用法（TPU 方阵里数据波一拍一格、HBM 16 层一层层抬起）；借 lemo/dataviz 的**同一比例**（128 根线和 5,120 根线按真实密度并排）
- 点子：观众以为 GPU 强在“算得快”，其实大模型更缺的是“搬得快”——HBM 用 40 倍的线把内存贴在芯片旁边，这也正是它贵、内存被抢光的原因。
- 对标：lemo/teardown 样片（`code/lemomo-ai__lemo-opuscar/3961ddb/styles/teardown/demo`；学：分层分离的节奏、标签和尺寸线的规格、镜头一直在走；不拿：键盘、橙色、PCB 贴图）；我们的 claude-teardown-3d-sim（11-02，同模板；学：深底 + 一个强调色的标签；不拿：那支用的是作者的录屏，这支是我们自己渲的 3D）。
- 结构候选：① 四颗芯片逐个看 → 为什么要 GPU（算 → 搬）→ 为什么贵 → 判断（用户要的顺序；第二钩子“真正卡住它的是搬数据”在约 30 秒）；② 先讲“搬数据”（35 倍）再回头认四颗芯片——钩子更强，但认芯片会像附录；③ 只讲 GPU，把 CPU / NPU / TPU 做成一张对照表——讲不深。选 ①：用户要的顺序，钩子先给结果（6 vs 200），中间每颗芯片 5 秒一个 3D 结构，30 秒处转到真正的机制。
- 风格：teardown 系统。底 #3A3D44 → #0C0D10 石墨径向；芯片自己的颜色（硅片深灰带清漆、基板深绿、铜、HBM 金边），版图：CPU 暖铜色大核、GPU 钢蓝 SM 方阵、TPU 深石板色乘加格；界面墨 #F1EFE9 两档（名称满、规格 66%）+ 强调金 #E0B84D；字：思源黑体 700（名称）、JetBrains Mono（规格、数字）、Barlow Condensed 800（钩子大数字）；字幕用 teardown 的居中无框字幕条（`captions: "tear"`）。
- 底色：全片一块石墨（产品是最亮的东西）；“搬数据”一段压暗到只剩总线和发光的数据包（低谷 / 转折）；高潮 35× 金色尺寸线；涨价一段 HBM 发金光。
- 贯穿物件：会冒出来的“字”（小方块）——钩子里 CPU 零星、GPU 成团；中段变成在总线上跑的数据包；结尾拉远时两颗芯片又在冒字。
- 招牌镜头：第 38–42 秒（bus 场）：镜头从 GPU 芯片沿着总线往内存方向滑，同一比例下左边 128 根线是一条细铜丝，右边 5,120 根铺成一整片铜，数据包像雨一样跑；金色尺寸线拉开「带宽 ≈35×」——配乐高潮落在这一拍。
- 第0帧：两颗芯片 + 冒字 + 「≈6 字/秒」「≈200 字/秒」+「同一个 80 亿参数模型 · 估算的理论上限」。
- 高潮停留：35× 尺寸线画完后停约 1.8 秒（镜头慢推，不切）；最后一句说完 0.3 秒内结束。
- 配乐：wonder，climax = bus，lifts = move、hbm；move 场开头静 0.4 秒（“可真正卡住它的是搬数据”）。
- 和上一支不同：最近三支 altman-dram-pc-waste（news-package）、weight-space-programming（telestrator）、deepseek-superagent（living-screencast）。结构（四个结构 → 一个机制 → 一个价格，不是原话核实 / 数字回放 / 演示）、开场（3D 两颗芯片冒字，不是真人原片 / 博客卡 / 重画群聊）、招牌（同比例总线 35×，不是晶圆卡 / 表上画线 / 结果表）、镜头路线（3D 连续运镜穿过物体，不是条带擦除 / 定格倒带 / 窗口推近）、配乐形状（wonder，高潮在机制不在价格）、结尾（拉远回到第 0 帧 + 判断）——六项都不同。第一支用我们自己的 3D。
