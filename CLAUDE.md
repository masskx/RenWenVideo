# RenWenVideo

Pipeline (Remotion, plus any web page rendered frame by frame) that turns an idea plus source material into short vertical videos (1080×1920, 30 fps) about AI tools and AI news. The same video goes to 微信视频号, 抖音 and 小红书. Viewer, niche and platforms are defined in one place: `docs/video-craft/quick-reference.md` §〇. All on-screen text is Simplified Chinese.

Input is **an idea plus material** (user, 2026-10-23: "from now on I'll only provide materials and ideas; you arrange the production script yourself"). I write the script, treatment and shots; a planner's ("growth") script or shot list is reference, not a spec — keep its facts, compliance notes and emphasis. Material may be images, images + video, or nothing: `docs/video-craft/导演方法.md` §一 says how to handle each.

## Priority order

1. Hook: the first 1–3 seconds must show and say the most interesting thing.
2. Retention: every few seconds something new happens (new number, new screen, new contrast); cut anything that doesn't earn its time.
3. Phone readability: big text, full-screen use, nothing important in platform UI zones.
4. Fidelity to the material and its sources (don't invent facts; label creator claims as claims).
5. Polish (motion design, transitions, sound) — only after 1–4 are satisfied.

## Workflow

**New session or container: run `npm run doctor` first** (dependencies, render browser, voice keys present, repo fonts, branch up to date with `main`); fix what it lists, then read the docs below. Everything learned so far lives in the repo (docs, `经验.md`, components), not in any session's memory.

Before templates: `douyin/agent-compute-hijack-v3` scored 7 ("及格了，之后做片再慢慢优化"), v2 scored 6 ("still too flat"). Knowledge videos are **2D first** (user: "像我这种只是分享知识的，还是优先在 2D 层面优化比较好"; no 3D engine unless asked). Start every new film from the v3 approach: props (`src/tutorial/props.tsx`) plus the 2D depth kit — lit drawings, floor line and grain (`Ground horizon/grain`), `ContactShadow`, a 2D camera (`camAt`) and parallax `Layer`s; see `src/tutorial/scenes/agent-compute-hijack-v3.tsx`. Characters act with `Person` in `src/tutorial/props.tsx` (jointed 2D figure: `walkPose`, `mixPose`, `POSE_SIT`; it points, types, turns its head, reaches, slumps — built 2026-10-28 for the first drafts of `anthropic-phd-career-reset` and `ai-more-work-burnout`, which were then remade on lemo templates); next: give it faces and hands that read at phone size. **Since 2026-10-28 every film starts from a template** (Workflow step 2); the news templates' parts are in `src/tutorial/package.tsx`. **Since 2026-11-01 every film carries the host IP** — the user's own cartoon, drawn in code from their profile picture, lip-synced to the narration (`src/tutorial/host.tsx`, config `"host"`, `docs/video-craft/IP形象.md`; look awaiting the user's OK): by default it waves in the hook, reacts at the twist, points at the climax and closes the ending, bottom-left above the captions.

Method: `docs/video-craft/导演方法.md` (built from the eight Opus-video repos, huashu-motion and Xian's 梵高 explainer; notes and "where each lesson is enforced" in `docs/video-craft/学习/README.md`). Read `docs/video-craft/经验.md` before each video. The six rules for every shot: one sentence one picture (no static text > 2 s), concrete props instead of abstractions, ground colour by emotion, visuals grown from the subject, one hero per frame, hold the climax ≥ 1.5 s.

1. **Input** — `inputs/<id>/`: `idea.md` (what to say, why now, facts with sources) plus material (screenshots, recordings, photos, links, numbers); skeleton `inputs/_template/`.
2. **Plan** — **first pick the template** (user, 2026-10-28: "for every new topic, find the most suitable template in the repository I gave you, apply it, then make the film"): the best fit from lemo-opuscar's 59 style templates or OPUSCAR 98 (`docs/video-craft/prompt-library/选用指南.md` §〇 maps topic → template), read its whole `STYLE.md`, and follow its system — layout, captions, package, type, grade, cutting, sound, native move — adapted to 9:16 (`src/lab/PackageLab.tsx` shows caption-news / news-package in 9:16); write it as `- 模板：lemo/<style>` (or `opuscar98/<n>`) in `## 导演` (`brief.mjs` fails a missing or unknown id). **Then customise it to the content** (user, 2026-10-28: "the templates make the videos look much more professional; customise them based on the content, using the examples I gave, so the videos don't all look the same"): 3–5 changes in `- 模板改造：` — palette found in this film's material, type, tempo, sound, at most one native move swapped, moves borrowed from up to two other templates / OPUSCAR 98; essence and engine stay (lemo `MY-STYLES.md`; `选用指南.md` §〇.3). `brief.mjs` fails a missing 模板改造 and warns when the same template was used in the last three films; log every film in `docs/video-craft/模板记录.md`. Then: one idea (not a list of points), a motif, 1–2 benchmarks from the library (`docs/video-craft/prompt-library/`, `node scripts/prompts/find.mjs`), three candidate structures, a style chosen **for this topic** from lemo / mg-styles-15 / huashu / Xian plus the account layer (`docs/video-craft/账号风格.md`), colours **found in the material** (`scripts/qa/palette.mjs`; never an invented house look), a medium (Remotion with `src/tutorial/props.tsx`, or a web page rendered with `scripts/page-render.mjs`, e.g. from a huashu template via `scripts/huashu-new.mjs`), and a storyboard `tutorials/<id>.storyboard.md` with `## 简报`, `## 导演` (ten required decisions) and `## 镜头表` (one row per sentence: the prop and what it does, framing, camera, reads, on-screen text). `node scripts/qa/brief.mjs <id>` must pass. **Prove the look first**: 3 style frames + frame 0 in real code (bench: `src/lab/PropsLab.tsx`), compared with the benchmark (`scripts/qa/compare.mjs`). Print the plan with the frames and wait for the user's OK. ≤ 60 s unless the user approves more (`"maxSeconds"`).
3. **Voice** — `npm run tutorial:voice -- <id>`: the user's MiniMax voice (default); word timestamps drive cues and subtitles. **Music** — every film gets a score (user, 2026-10-26): set `"score": {"mood", "climax", "lifts"}` in the config, run `npm run tutorial:score -- <id> --preview` and check `qa/<id>/score-preview.mp3`; the render composes it automatically when it is missing or older than the voice timeline (levelled against the narration — never hand-set musicVolume back to 0.07). MiniMax's music API is closed to this account (HTTP 410), so the score is synthesized; `docs/video-craft/音效.md` §六.
4. **Render** — `npm run tutorial:render -- <id> --overwrite` (1080×1920 H.264, covers); page scenes via `node scripts/page-render.mjs pages/<id>/<scene>`.
5. **Review** — machine checks (`node scripts/qa/brief.mjs <id>`, `echo.mjs <id>` (on-screen text echoing the narration > ⅓ fails), `cover.mjs <id>`, `richness.mjs` / `marks.mjs` / `scan.mjs --phone` / `clutter.mjs` on the mp4, `npm run lint`) are the floor, not the goal. Then: contact sheets, 0.1–0.2 s strips of key moves, crops; side by side with the benchmark and our last three films (`compare.mjs` — at least four of structure / opening / signature shot / camera path / score shape / ending must differ); an independent jury pass (`node scripts/qa/jury.mjs <id>`, rubric `docs/video-craft/评审表.md`; a subagent only when the user allows, else a self-review marked as such); fix the top three issues and look again.
6. **Package** — `douyin/<id>/`: mp4 (committed; < 100 MB), covers, stills, README with separate title / description / hashtags for 视频号, 抖音, 小红书, and credits. Then add a line to `docs/video-craft/经验.md` and ask the user for a 1–10 score and one sentence.
7. **Learn from the numbers** — when the user shares a platform export (抖音 creator-centre 作品数据 .xlsx): `python scripts/stats/douyin-export.py <xlsx> --since=<date> --out=docs/video-craft/数据/<date>.md` matches each post to its film, length and first line; write what changed into `经验.md` / `hooks.md` and the checks. Never commit the export itself. What the data says so far (2026-10-26, `docs/video-craft/数据复盘-2026-10-26.md`): viewers stay 6–16 s on average, so the first line is a concrete event + a number / moment (no date, greeting or "this video" opener — `brief.mjs` fails it), the core number lands in the first 10 s, explainers run 35–50 s, long films only as save-worthy tutorials, and risk topics end on one action the viewer can take now.

## Hard rules

- Narration (user, 2026-10-24: "from now on, when you help me make videos, always use this new MiniMax voice"): the user's MiniMax voice `MashuaiDouyin01` (T2A v2, `speech-2.8-hd`, key `MINIMAX_API_KEY`; reads Chinese with English nouns mixed in). It is the default (`"tts": {"provider": "minimax"}`, or no `tts` at all). The earlier cloned Doubao voice stays available (`"provider": "doubao"`, `DOUBAO_API_KEY`, `DOUBAO_VOICE_ZH`) for older films or when the user asks for it. Never print or commit keys. edge-tts (`"provider": "edge"`) is a backup only when the user agrees — never a silent fallback. Details: `docs/video-craft/配音.md`.
- Don't invent facts or numbers; label creator claims (「据 @作者」); first person only for things that really happened.
- External footage: muted, bottom-right label 「@作者｜案例展示」, author link in the package README.
- The hook is mine to design from the material (references: `docs/video-craft/hooks.md`); say in the plan what it is and why.
- `npm run lint` must pass; each mp4 < 100 MB; record new failure modes in `docs/video-craft/踩坑清单.md`.
- Cloud container: renders find the installed headless shell themselves (`chromium_headless_shell-1243/chrome-headless-shell-linux64/chrome-headless-shell`, older images `chromium_headless_shell-1194/chrome-linux/headless_shell`; override with `REMOTION_BROWSER_EXECUTABLE`); `TTS_CA_BUNDLE=/root/.ccr/ca-bundle.crt` for the edge-tts backup.
